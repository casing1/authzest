# 모델 전략과 평가

[문서 목차](INDEX.ko.md) · [개발 계획](DEVELOPMENT_PLAN.ko.md)

## 결정

설치형 CLI와 기존 core/adapter 경계를 유지합니다. 특정 GPT 출시를 중심으로 제품을 다시 만들지
않습니다. AuthZest가 제공하려는 가치는 반복 가능한 소스 근거, 명시적 정책 기대 조건, 검토 가능한
설명과 측정한 한계입니다. 같은 작업을 모델에 직접 맡기는 것보다 도움이 되는지는 이미 입증한
장점이 아니라 검증할 가설입니다.

현재 제품은 제한된 FastAPI 라우트 구문을 목록화합니다. 의존성 근거 수집, 인가 정확성 판정과
AI adapter 실행은 아직 없습니다. [소스 전용 예제](EXAMPLES.ko.md)는 파서 회귀 검사와 데모이며
보안 벤치마크가 아닙니다.

## 안정적인 계약과 교체 가능한 모델

| 계층                | 책임                                                          | 뜻하지 않는 것                                  |
| ------------------- | ------------------------------------------------------------- | ----------------------------------------------- |
| Parser와 analyzer   | 결정론적 선언, 원본 위치, 지원하는 등록 맥락                  | 임의 Python의 완전한 이해                       |
| 정책과 리포트       | 관찰한 사실, 사용자 기대 조건, 미해석 근거와 향후 검사를 분리 | 의존성 선언만으로 인증·인가 증명                |
| 선택적 adapter      | 의도적으로 선택한 근거를 설명하고 응답 형식과 참조 검증       | 모델의 근거 없는 주장을 확인된 finding으로 승격 |
| CLI와 선택적 API/UI | 같은 core 리포트와 정확한 실패·부분 결과 상태 표시            | 성공 종료나 라우트 0개가 보안 통과              |

파서를 범용 Python 인터프리터로 확장하지 않습니다. 문서화한 사용 사례와 유지하는 fixture가
필요성을 뒷받침할 때만 구문 지원을 추가합니다. 반복 mount에는 구별되는 등록 식별자와 app/include
위치 근거가 필요하며 URL 경로나 handler 위치만으로는 맥락을 식별할 수 없습니다. 확인한 미해석
사례는 기록하되 모든 미지원 구문을 발견할 수 있다고 주장하지 않습니다.

다음 선행 작업은 [#32: 리포트와 등록 계약](https://github.com/casing1/authzest/issues/32)이며,
이후 [#28: 라우트 직접 선언](https://github.com/casing1/authzest/issues/28),
[#29: 상속 선언](https://github.com/casing1/authzest/issues/29) 순서입니다.
버전, 진단, 결정론적 순서, 호환성과 CLI 종료 동작을 명시합니다. 현재 parse error가 있어도
종료 코드 0일 수 있으며, 이 문서가 향후 계약을 구현하는 것은 아닙니다.

## 실제 연동 이전의 AI 경계

[#33: 근거에 연결된 설명과 오프라인 평가](https://github.com/casing1/authzest/issues/33)부터 시작합니다.
실제 연동 방식 하나를 고르기 전에 최소 근거 payload와 mock adapter 테스트를 정의합니다.
기본 스캔과 CI에는 제공자 호출, 자격 증명, 구독이나 유료 모델이 필요하지 않습니다.

나중에 추가할 opt-in adapter는 명시적 데이터 공유 승인과 허용 입력 범위 확인이 필요합니다.
저장소 텍스트는 신뢰하지 않는 데이터이며 모델에 도구나 접근 권한을 부여하는 지시가 아닙니다.
소스 내용을 최소화하고 비밀정보를 처리하며 timeout, 취소, 잘못된 출력, 제공자 사용 불가와
지원하지 않는 참조의 동작을 정의합니다. adapter가 실패해도 로컬 리포트는 유지해야 합니다.

각 설명을 제공한 근거 식별자와 대조하고 추정한 정책을 사람이 선언한 정책과 분리합니다.
공개 endpoint와 일반적인 의존성 주입은 정상 사례이며, 인식 가능한 인가 근거가 없다는 사실만으로
취약점이라고 하지 않습니다.

adapter가 생기면 제공자/모델을 설정으로 선택하게 합니다. 실제 반환된 모델 식별자, prompt/adapter/report
버전, 소스 revision 또는 내용 식별값, 허용 입력 목록과 확보 가능한 실제 사용량·지연 시간을 기록합니다.
새 모델로 조용히 바꾸거나 없는 사용량을 만들어내지 않습니다. 민감한 소스와 자격 증명은 telemetry에서
제외합니다. CLI와 App Server는 인터페이스 뒤의 연동 선택지이며 텀프에서 동시에 구현할 요구가 아닙니다.

## 제품 가설 검증

prompt를 조정하기 전에 직접 소유하는 작은 로컬 fixture와 예상 정책 label을 사람이 검토하고 고정합니다.
일반 DI, 의도적 공개 라우트, 관련 접근통제 선언, 반복 mount, 불완전 입력과 미지원 패턴을 포함합니다.
예상 정답은 모델 입력에서 제외하고 일부 사례는 prompt 개발이 아닌 평가용으로 남깁니다.

같은 작업과 허용 소스/정책 범위로 세 모드를 비교합니다.

1. AI 없는 정적 근거.
2. AuthZest가 추출한 근거 없이 허용 소스와 정책을 모델에 직접 제공.
3. 같은 모델에 같은 범위와 AuthZest 근거를 함께 제공.

두 AI 모드의 모델과 작업 지시를 비교 가능하게 유지하고, 불가피한 입력 차이를 기록하며 같은 비용이라고
주장하는 대신 실제 token 사용량을 기록합니다. 비결정론적 모드는 반복 실행합니다. 정적 전용 모드는 설명
작업에 답하지 못할 수 있으므로 답변 보류를 정답으로 세지 않고 작업 지원 범위와 정확성을 나눠 보고합니다.

라우트/선언의 정확성과 지원 범위, 올바른 소스 인용, 근거 없는 주장, 정책 일치, 미해석 결과, 반복 실행
변동, 지연 시간, 실제 사용량과 사람의 검토 노력을 측정합니다. 종합 점수와 함께 분모, fixture 한계와
대표 오류를 보고합니다. 라우트가 많거나 unknown이 적다는 사실만으로 더 좋은 보안 분석은 아닙니다.
목록화 fixture와 나중에 추가할 정책 label 평가 집합을 구분합니다.

근거 계약과 초기 의존성 fixture가 준비되면 작은 비교를 시작할 수 있으며, 완성된 결정론적 finding 엔진이
선행 조건은 아닙니다. 근거 보조 모드가 도움이 되지 않으면 agent 자율성을 늘리는 대신 주장을 좁히거나
작업 흐름을 수정합니다.

## 설계의 참고 근거

2026-09-10에 공식 문서를 확인했습니다. 모델 기능과 권장은 변하므로 교체 가능한 경계에서 모델을 선택합니다.
이는 우리의 구조적 판단이며 AuthZest 성능이 입증됐다는 뜻은 아닙니다.
[OpenAI 모델 가이드](https://developers.openai.com/api/docs/guides/latest-model).

작업별 데이터셋, 전문가 label, 명시적 지표, 비교와 반복 평가를 위 평가 과정의 참고로 삼았습니다.
[OpenAI 평가 가이드](https://developers.openai.com/api/docs/guides/evaluation-best-practices).

App Server 문서의 인터페이스와 관리형 인증 흐름은 나중에 검토할 수 있습니다. 문서를 읽는 것만으로
adapter가 활성화되거나 저장소 데이터를 전송할 권한을 얻는 것은 아닙니다.
[Codex App Server 문서](https://learn.chatgpt.com/docs/app-server).
