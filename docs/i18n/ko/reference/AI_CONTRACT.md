# 오프라인 AI 계약과 평가

[문서 목차](../INDEX.md) · [모델 전략](../development/MODEL_STRATEGY.md)

## 상태와 범위

소스 checkout에 #33의 오프라인 기반을 구현했습니다. alpha.2 바이너리에는 포함되지 않습니다.
AI 스키마 `1.0`은 숫자 temperature 요청의 호환 기본값입니다. 스키마 `1.1`은 제공자 관리 sampling을
위한 `temperature: null`을 추가로 허용합니다. 스캔 리포트 스키마 `1.2`, 패키지 버전 `0.1.0a2`와는
별개입니다. 기존 숫자 요청과 식별값은 유지하고 `AdapterConfig` temperature 기본값은 `0.0`입니다.
null은 0이나 결정론적 출력을 뜻하지 않습니다. 계약 자체는 제공자 호출이나 파일 적용을 하지 않습니다.
별도의 [#50 소유 fixture 명령](../guides/CODEX_FIXTURE.md)은 고정 App Server 초안에 nullable 스키마를
사용하며 한 소유 fixture의 실제 초안·적용·복구 확인 1회가 성공했습니다. 기본 스캔 JSON/종료는 그대로이며 오프라인을 유지합니다.
완전한 #35 흐름, 일반 저장소 AI와 런타임 검증은 미완료입니다.
사용하지 않던 `CodexFinding` 초안은 제거했고 adapter는 finding이 아닌 비신뢰 JSON을 반환합니다.

## 입력과 식별값

`prepare_request`는 기존 리포트, 명시적으로 고른 등록 ID, 호출자가 제공한 저장소 상대 경로 소스
스냅샷, 선언 정책, 질문과 `AdapterConfig`를 받습니다. 저장소 파일을 직접 열지 않습니다.
호출자는 동일하게 검토한 소스 상태에서 리포트와 스냅샷을 수집해야 합니다.
소스·정책은 비신뢰 데이터이며 도구 허가나 시스템 지시가 아닙니다.

- 각 소스/라우트/정책/한계 항목은 내용 기반 `ev-` 식별값을 가집니다. 라우트에는 리포트의
  `route-` 등록 ID, 원본 위치와 의존성 근거가 남습니다. 참조 위치는 제공한 스냅샷 안에 있어야
  하며 반복 mount는 구별됩니다.
- 요청에는 저장소 루트, 원문 파싱 오류와 진단 메시지를 넣지 않습니다. 선택한 진단 코드/개수와
  bounded/partial 상태는 명시하지만 보안 판정으로 취급하지 않습니다.
- 소스 식별값은 제공한 경로/텍스트를 해시합니다. 요청 식별값에는 근거, 질문, 정책, 모드, 스키마와
  설정도 포함됩니다. 선택적인 소스 revision은 호출자 제공값이며 Git과 대조하지 않습니다.
  어느 식별값도 런타임 보장이나 패치 승인 토큰이 아닙니다.
- 제한은 소스 16개, 파일당 32,768자, 근거 256개, 질문 32개, JSON 262,144바이트, 중첩 깊이 32와
  JSON 노드 8,192개입니다. 상대 경로가 아닌 입력, 없는 등록, 중복 ID/키, 비호환 버전,
  비유한 수와 잘못된 Unicode를 거부합니다.
- `CodexAnalysisRequest`는 불변 JSON을 저장하고 `to_dict()`는 분리된 미리보기 사본을 반환합니다.
  선택적인 검토 서비스에는 정확한 요청 ID 승인이 필요합니다. 미승인 또는 변경된 입력에는
  adapter 호출 전에 `not-approved`를 반환합니다. 이 프로그램 내부 검사는 사용자 동의 UI가 아닙니다.

입력 선택은 자동 비밀정보 탐지나 익명화가 아닙니다. 모든 실제 호출 전에 사용자가 정확한 스냅샷을
검토하고 비밀/비공개 내용을 제거해야 합니다. 라이브러리는 자격 증명을 읽거나 동의를 추정하거나
API 클라이언트를 제공하거나 저장소 텍스트를 명령으로 바꾸지 않습니다.

## 응답과 실패 처리

`validate_response`는 현재 스키마/요청 ID 및 정확한 provider/model/adapter/prompt 식별값을 요구합니다.
몰래 모델을 바꾸면 거부합니다. 모든 질문에 기존 근거 ID, 설명, 가정, 불명확 사항과 검토 질문을
포함한 응답이 정확히 하나씩 있어야 합니다.

허용 상태는 `hypothesis`, `unknown`뿐입니다. unknown에는 null 답변과 한계 설명이 필요합니다.
확정 finding/severity/추가 필드를 거부하며 결정론적 원본 리포트를 모델 주장으로 교체하거나
수정하지 않습니다. 모델 출력은 별도로 반환합니다.

구조 검증으로 자유 형식 문장이 참인지 또는 유효한 인용이 실제 주장을 뒷받침하는지는 알 수 없습니다.
악의적이거나 잘못된 설명도 스키마 검사를 통과할 수 있습니다. 의미상 근거 없는 주장은 사람 검토가
필요하며 스키마 통과를 확정 진단으로 표시하면 안 됩니다.

`review_report`는 입력/설정 식별값, 반환 식별값, 제공자가 보고한 nullable 토큰 수와 실제 로컬 왕복
시간을 기록합니다. 비용/토큰 수를 만들어내거나 원문 소스/제공자 예외를 로그로 남기지 않습니다.
mock은 모델 사용량을 보고하지 않습니다. adapter 실패·사용 불가·잘못된 출력·timeout에도 원본
리포트를 보존합니다. 취소는 호출자와 협조적인 비동기 adapter에 전달됩니다. timeout은 OS 격리가
아니며 블로킹/비협조적 transport를 중단할 수 없습니다. 별도 fixture adapter는 자체 프로세스 정리와
권한 검사를 추가하지만 이 범용 서비스가 OS sandbox인 것은 아닙니다.

## 오프라인 평가 재현

editable 개발 환경을 설치한 뒤 저장소 루트에서 실행합니다.

```bash
python scripts/evaluate_offline.py --repeats 2
python -m pytest tests/test_ai_contract.py tests/test_ai_evaluation.py
```

실행기는 `tests/fixtures/ai_evaluation/v1/`의 유지하는 소스 전용 평가셋만 읽습니다.
앱을 import/실행하거나 제공자를 호출하지 않습니다. 여섯 사례는 공개 의도, 일반 DI, scope 선언,
반복 mount, 동적 prefix와 미해석 의존성입니다. 세 개는 개발용이고 세 개는 향후 프롬프트 평가를 위해
보류한 held-out 사례입니다. 비밀 데이터라는 뜻은 아닙니다.

`dataset.json`에는 질문과 선언 정책, `mock_answers.json`에는 명시적인 고정 transport 응답이 있습니다.
`labels.json`은 평가자 전용이며 모든 요청/응답을 준비한 뒤 읽습니다. 두 mock 모드는 동일한 소스,
정책, 질문과 모델 설정을 사용하며 추출 근거만 다릅니다. 정적 모드는 지원하는 목록 사실만 답하고
정책 해석은 보류합니다. 채점을 위해 공통 응답 형식을 사용할 뿐 AI 호출은 아닙니다.
해시 테스트로 모든 평가셋 파일을 고정합니다.

관리자는 2026-09-10에 다섯 정책 기준을 승인했습니다. 예상값 초안은 assistant가 작성하고 소스와
코드로 대조했으며 사람이 직접 작성한 정답이나 독립된 벤치마크 검토 완료로 표시하지 않습니다.
소스·정답·질문·고정 응답 변경에는 명시적 평가셋 검토와 해시/버전 갱신이 필요합니다.
held-out 사례로 프롬프트를 조정하지 마세요.

기본 실행은 6개 사례 × 3개 모드 × 2회인 36회입니다. JSON에는 사례별 split, 분모를 포함한
답변 정확도/범위, unknown 처리, 정책 일치도, 참조 유효성, 출처와 첫 회 대비 반복 출력 변화가
포함됩니다. 잘못된 응답에는 과제 점수를 주지 않습니다. 답변 보류를 정답으로 세지 않으며
올바른 unknown 처리는 별도 측정합니다.

근거 없는 주장을 포함한 답변 수(오해를 주는 보류 포함)와 측정한 사람 검토 시간을 채점 라이브러리에
제공할 수 있지만 무인 실행기는
null로 둡니다. 측정하지 않은 회차가 있으면 합계도 null이며 사람이 채점한 회차 수를 별도로 표시합니다.
없는 토큰 수도 0이 아니라 null입니다. mock 점수로 AI의 효과, 인가 정확성이나 안전한 모델 교체를
주장하면 안 됩니다. 실제 반복 실행, 독립적인 의미 검토, 사용량과 검토 수고 측정은 이후 별도 승인한
실제 평가에서 수행해야 합니다.

## 실제 연동 경계와 남은 작업

후속 [제안/결정 계약](PROPOSAL_CONTRACT.md)(#46)은 내부 제안 연결·미리보기·만료/변경 상태 검사만
구현합니다. 실제 adapter·동의 UI·파일 적용 서비스·검증 실행기가 아닙니다. 별도
[#48 복사본 전용 데모](../guides/FIXTURE_APPLICATION.md)는 새 POSIX fixture 복사본에 터미널 결정과
적용/복구를 추가합니다. #50의 별도 버전 고정 App Server 명령은 명시적인 공유와 소유 fixture의 모델
초안을 추가하지만 오프라인 평가를 실제 모델에 실행하거나 일반 저장소를 받거나 런타임 검증을 실행하지는
않습니다. 한 fixture의 실제 확인에서 승인 문구는 사용자 허가 아래 assistant가 입력했으며
독립적인 사람 검토는 아닙니다. 상위 #35는 계속 미완료입니다.
이 명령의 후속 #52 선택적 고정 소스 검사는 별도 승인한 계획과 자식 프로세스로 적용된 fixture의
해시를 고정하고 AST 설정을 확인합니다. 대상 소스를 실행하지 않으며 AI 응답 계약도 바꾸지 않습니다.

정확한 소스/정책 스냅샷, 제공자/모델 식별값, 개인정보/데이터 처리와 예산을 별도로 승인받아야 합니다.
transport 하나를 고르고 실제 반환 식별값과 확인 가능한 사용량을 기록합니다. 자동 대체나 모델 교체는
허용하지 않습니다. 소스 공유 승인은 패치나 검증 실행을 허가하지 않습니다. #35에서 정확한 제안 diff와
제한된 검증 계획을 각각 별도로 승인해야 하며 거절·취소·입력 변경·실패 시 사용자 편집을 보존해야 합니다.
