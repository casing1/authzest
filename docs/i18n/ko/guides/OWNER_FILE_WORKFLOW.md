## 제공 범위와 한계

이 미출시 #82 소스 구현은 `codex-owner-repair --file-workflow`를 기존 파일 세션 API에 연결합니다.
플래그를 생략하면 기존 추천 전용 동작을 유지하며 복사본 생성·정책 실행·적용·복구를 하지 않습니다.
공개 alpha.3와 패키지 버전 `0.1.0a3`는 그대로입니다. 선택적인 웹 대시보드는 이 흐름을 표시하거나
제어하지 않습니다.

활성 파일 경로는 **POSIX의 non-frozen Python 소스 모드**와 지원하는 descriptor 상대경로
파일시스템 기능이 필요합니다. 지원하지 않는 플랫폼은 제공자 접근·복사본 생성 전에 거절합니다.
Windows/frozen 실행 파일도 이식 가능한 오프라인 공유 미리보기는 표시할 수 있습니다.
저장소 경로·저장 위치·소스·worker·승인 증표 가져오기·세션 재개 옵션은 없습니다.

등록된 합성 소유자 비교 생략 쌍과 검토된 사례 8개만 지원합니다. 모델은 등록 템플릿을 선택하고
host가 정확한 diff를 도출합니다. 임의의 AI 생성 코드 수정, HTTP 인가 검증, OS sandbox나 보안
보장이 아닙니다. 기존 Codex ChatGPT 로그인과 고정 adapter는 그대로이며 API key를 추가하지 않습니다.

이 구현은 임시 파일·가짜 adapter·scripted worker 응답으로 검증합니다. 이 응답은 **정책 관찰이
아닙니다.** 이전에 별도 승인한 소스 API 관찰은 연결된 참조 문서에 있으며 새 CLI의 실제 수용을
입증하지 않습니다. 새 설치 흐름/제공자/worker 수용과 필수 리뷰 조건은 #82/#81/#35에 열려 있습니다.
문서 예제는 실제 실행을 허가하거나 수행하지 않습니다.

## 부작용 없는 미리보기

이 변경을 포함한 소스 설치를 사용하세요. `YOUR_EXACT_MODEL_ID`는 기존 Codex 계정에서 사용 가능한
정확한 모델의 자리표시자이며 자동 모델 선택이 아닙니다. 다음 명령은 오프라인이며 인증이나
제공자/worker 프로세스가 필요하지 않습니다.

```bash
authzest codex-owner-repair --model YOUR_EXACT_MODEL_ID --file-workflow --preview-only
authzest codex-owner-repair --model YOUR_EXACT_MODEL_ID --candidate after --file-workflow --preview-only --json
```

미리보기 전용 경로는 의도적으로 기존 **공유 미리보기**를 그대로 사용합니다. 전체 고정 소스·기준·
가정·예상값·프롬프트·스키마·모델/설정과 새 공유 확인 문구를 표시합니다. 복사본이나 파일 단계
계획을 만들거나 가상의 파일 승인 식별값을 출력하지 않습니다. 미리보기 전용 확인 문구는 이후
호출을 승인할 수 없습니다. `--file-workflow`는 선택자이지 **동의가 아니며**, 플래그나 공유 승인
어느 쪽도 파일 효과를 허용하지 않습니다.

## 대화형 순서 — 별도 결정

아래 명령은 활성 경로이며 오프라인 smoke 검사가 아닙니다. 공유와 각 로컬 효과를 검토할 의도가
있을 때만 실행하세요. 제공자 요청은 계정 사용량을 소비할 수 있습니다. 기존 애플리케이션 1회 시도/
120초 제한이 Codex 내부 재시도나 사용량까지 별도로 제한하지는 않습니다.

```bash
authzest codex-owner-repair --model YOUR_EXACT_MODEL_ID --candidate before --timeout-seconds 120 --file-workflow
```

사람용 요약뿐 아니라 모든 전체 JSON 미리보기를 확인하세요. **현재** 호출이 표시하는 정확한
문구를 입력합니다. Enter는 거절, `cancel`은 해당 선택의 취소입니다. 일치하지 않는 문구는
재시도가 아닌 거절입니다. EOF나 인터럽트는 이후 복구 질문에 대신 답하지 않고 대화를 중단합니다.
무인 승인 플래그나 자동 복구는 없습니다.

| 단계   | 정확한 문구                          | 별도로 허용하는 효과                                                                       |
| ------ | ------------------------------------ | ------------------------------------------------------------------------------------------ |
| 공유   | `share <sharing_id>`                 | 기존 adapter로 추천 1회 시도. 정책 실행·복사본 생성은 없음.                                |
| 복사본 | `copy <session_id> <application_id>` | 등록 before 정책과 보존 증거 파일의 새 비공개 임시 복사본 하나 생성.                       |
| Before | `approve before-check <plan_id>`     | 고정 worker에서 캡처한 before 파일 바이트 검사. 예상한 사례 불일치는 기반시설 실패가 아님. |
| Diff   | `approve diff <plan_id>`             | host가 도출한 정확한 diff 수용. 파일 교체는 없음.                                          |
| 적용   | `approve apply <plan_id>`            | 세션이 소유한 `policy.py`만 등록 after 바이트로 교체.                                      |
| After  | `approve after-check <plan_id>`      | 내장 after 대조군이 아닌 캡처한 적용 파일 바이트 검사.                                     |
| 복구   | `approve restore <plan_id>`          | 추적 중인 파일과 증거가 확인된 경우에만 등록 before 바이트로 복구.                         |

복사본 생성 전에 현재 추천과 전체 요청 연결을 재검증합니다. `no-change`·`unknown`은 복사본 없이
정상 종료합니다. `registered-change`는 `before`에만 유효하며 `after` 응답은 수정을 선택할 수
없습니다. 과거 제공자 응답·JSON 결정·저장된 checkpoint를 현재 권한으로 가져올 수 없습니다.

복사본 결정과 준비한 각 단계는 최대 **300초** 안에 만료되며 한 번만 시도합니다. 계획을 읽거나
표시해도 만료 시간이 연장되지 않습니다. 실제 효과 경계에서 파일 식별값·바이트·결정 유효성·선행
조건을 다시 확인합니다. CLI를 새로 실행하면 새 공유 결정으로 시작하며 보존 복사본을 재개하거나
소비된 승인을 재사용하지 않습니다.

Before/diff/적용을 거절하면 앞으로 진행하지 않습니다. After 검사 거절·실패 후 확인된 적용
복사본이 남았다면 CLI는 **새 별도 승인 복구 계획**을 제시할 수 있습니다. 사용자 편집·없거나
확인되지 않은 증거·불확실한 쓰기는 안전하지 않은 진행/복구를 차단합니다. 인터럽트는 자동 복구를
유발하지 않습니다. 수동 후속 작업 전에 최종 checkpoint와 보존 파일을 확인하고, 명령 실패가
아무 변경도 없었다는 뜻이라고 가정하지 마세요.

## 사람용 출력·JSON·보존 상태

사람용 출력은 제공자 식별/사용량, 실행, 예상값 대비 관찰 비교, 적용, 복구, 파일 연결과 증거를
구분합니다. 사례 8개 표는 관찰이 없으면 unknown으로 둡니다. 데이터 값은 ASCII 인용/이스케이프하며
모델 설명문이나 표시 경로는 지시가 아닙니다. 효과 결정 전에는 전체 원본 JSON을 계속 표시합니다.

`--json`을 추가하면 **stdout에는 최종 JSON 문서 하나**를, stderr에는 대화형 미리보기·질문·
진행을 출력합니다. `--preview-only --json`의 stdout에는 전체 공유 미리보기만 있습니다.
활성 결과 kind는 `codex-owner-file-workflow`이며 `file_workflow.session_result`에 확보 가능한
현재 비인증 파일 checkpoint가 있습니다. 바깥 제공자 식별/사용량/지연시간은 추천 요청을 설명하며
중첩 순수 데이터 미리보기의 0회 호출로 이 값을 대체해서는 안 됩니다.

실행 완료가 비교 통과를 뜻하지는 않습니다. 완료된 before 검사도 예상한 두 불일치를 포함할 수
있습니다. 복구 후 과거 after 비교 통과는 이전 적용 바이트를 설명하며 **현재 복구된 before 파일의
통과가 아닙니다.** 복구는 어느 검사도 다시 실행하지 않습니다. 실패 결과는 일괄 `not-run` 대신
부분 효과와 개별 복구 상태를 보존합니다. 생성된 세션의 현재 checkpoint를 확보할 수 없다면 상태
불명이지 미실행 증명이 아닙니다. 정상 `no-change`/`unknown`이나 복사 전 거절은 별도로 복사본
미생성을 표시합니다.

완료·거절·실패·취소 후에도 복사본과 기록은 디스크에 남습니다. 닫기는 descriptor를 해제할 뿐
작업공간을 삭제하거나 `record.json`을 다시 쓰지 않습니다. 따라서 최종 메모리의 `closed` 값과
마지막 디스크 기록이 다를 수 있습니다. 어느 쪽도 인증된 증표나 재개 가능한 세션이 아니며 인가는
`unknown`입니다. 로컬 경로·세션/계획 식별값·원시 기록은 비공개 정보일 수 있으므로 이슈 보고 전에
확인하고 가리세요.
