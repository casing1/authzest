# 로컬 워크플로 결과 화면

[문서 목차](../INDEX.md) · [생성 파일 흐름](GENERATED_FILE_WORKFLOW.md)

소스 대시보드는 사용자가 직접 선택한 소유자 조회 또는 생성 파일 흐름 JSON과 기존 정적 라우트
목록을 표시합니다. 로컬에서 실행하므로 웹사이트 배포가 필요하지 않습니다. 일반 실행은 읽기 전용이며
아래 명시적 owner-read 모드는 CLI와 같은 엔진에 공유·실행·복사본 적용·복구의 별도 현재 GUI 결정을
연결합니다.

## 지원하는 소스 설치

Python 3.12와 npm을 준비한 뒤 소스 checkout에서 실행합니다.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[ui]'
cd frontend
npm ci
npm run build
cd ..
.venv/bin/authzest ui --workspace .
```

`http://127.0.0.1:8000`을 엽니다. 서버를 유지하고 Ctrl-C로 종료합니다.
`authzest ui --help`에서 `--host`, `--port`, `--reload`, `--workspace`, `--ai-runtime-config`를 확인할 수 있습니다.
Workspace는 정적 스캔 대상을 고정하며 결과 폴더를 지정하는 옵션이 아닙니다. UI 소스를 바꾸면
frontend를 다시 빌드합니다. API가 `frontend/dist`를 찾도록 editable 소스 설치를 사용하는 경로입니다.
Wheel과 native 스캔·미리보기 바이너리에는 완전한 UI·활성 흐름 설치가 들어 있지 않습니다.

## 로컬 AI 흐름 실행

이 선택 모드는 POSIX non-frozen Python 소스 설치에서 관리하는 소유자의 보관 노트 사례를 지원합니다.
기존 Codex ChatGPT 로그인과 검토한 로컬 owner-read Docker 런타임을 사용합니다. 임의 저장소를 받거나
원본 checkout에 적용하지 않습니다. 먼저 [소유자 조회 계약](../development/GENERATED_REPAIR_CONTRACT.md#승인형-복사본-흐름-실행)에
따라 비공개 런타임 설정과 이미지를 준비·검토합니다. 서버 시작 때 절대 로컬 profile 경로를 지정합니다.

```bash
.venv/bin/authzest ui --workspace . --ai-runtime-config /ABSOLUTE/PRIVATE/runtime.json
```

이 모드는 숫자형 loopback `127.0.0.1`, 앱 인스턴스 하나와 reload 비활성을 요구합니다. CLI가 표시한
비공개 실행 URL을 엽니다. `authzest-ai` fragment에는 새 실행 capability가 있으며 페이지가 fragment를
지운 뒤 토큰을 메모리에만 유지합니다. 실행 URL을 공개하지 마세요. 일반 `http://127.0.0.1:8000`
접속이나 저장 결과 가져오기는 활성 권한을 얻지 않습니다. 같은 출처에서 제공한 빌드 대시보드를 사용하며
Vite 개발 proxy는 활성 출처 예외가 아닙니다. 페이지 새로고침 뒤에는 비공개 실행 URL을 다시 열어 현재
메모리 내 실행에 재연결합니다. 서버 재시작은 capability를 무효화하며 이전 작업을 재개하지 않습니다.

1. AI 흐름을 열고 필요하면 설치한 Codex 버전·로그인 준비 상태를 확인합니다. 모델 요청 없이 간략한
   상태만 표시하며 계정 세부정보를 보내지 않습니다. 새 OAuth 로그인 화면·API key 양식은 없으며
   기존 Codex 로그인을 사용합니다.
2. 정확한 모델 ID를 입력하고 실행 하나를 시작합니다. 시작은 소스 공유 승인이 아닙니다.
3. 현재 전체 계획을 읽고 런타임·공유·복사본·before·diff·적용·after·복구마다 표시한 정확한 문구를
   각각 직접 입력합니다. 결정은 일회성이며 core의 원래 최대 300초를 유지하고 미리 보낼 수 없습니다.
   필요에 따라 거절하거나 중단합니다.
4. 제한된 호스트 활동을 확인하고 생성 코드·테스트·호스트 계산 diff·before/after 관찰·복구 상태를
   검토합니다. 활동 표시는 모델 토큰 스트림과 다릅니다. no-change·unknown·refused는 복사본을 만들거나
   수정 성공을 뜻하지 않습니다.
5. 브라우저의 저장·다운로드 기능으로 전체 최종 JSON을 익숙한 비공개 위치에 저장합니다. API는 서버
   저장 경로를 받지 않습니다. JSON과 보고된 비공개 복사본·복구 파일을 검토용으로 유지하세요.
   projection 실패 시 표시 자료는 없음으로 남으며 성공으로 바꾸거나 제한 안의 다운로드 JSON을 지우지
   않습니다.

조정기는 현재 실행 하나와 완료 결과 하나를 유지합니다. 새 실행은 소유 worker가 끝난 실행만 교체합니다.
결과가 있으면 다음 실행 전에 다운로드하세요. 화면이 `finished` 또는 `failed`를 받으면 세션 반복 조회를
멈추고 새 실행이 시작되면 갱신을 재개합니다. 실행 중·결정 대기·중단 처리 중에는 계속 갱신합니다.
AI 탭을 다시 열면 현재 세션을 조회합니다. 시작 응답이 유실되거나 충돌하면 시작을 재시도하지 않고
세션만 한 번 확인합니다. 연결 오류가 나면 연결이 복구될 때까지 읽기 전용 세션 조회를 재개할 수 있으며
접근 권한 오류에는 조회를 중단합니다. 반복 조회는 결정을 승인하지 않으며 브라우저 종료는 worker를 중단·재시작하지
않습니다. 현재 계획은 2 MiB, 최종 JSON은 4 MiB, 활동은 256개 event로 제한합니다. 아래 저장 결과
가져오기는 별도의 512 KiB 제한이 있으므로 더 큰 다운로드 결과가 해당 경로로 다시 열릴 것을 보장하지
않습니다.

중단 요청은 협력적으로 처리합니다. 실행 중인 요청·guest는 엔진이 안전한 중단 지점에 도달하기까지
기존 제한 시간·정리를 기다릴 수 있으며 `stopping`은 종료 확인이 아닙니다. 적용 후 중단하면 복구 필요
상태가 남을 수 있고 자동 복구하지 않습니다. after 검사를 빈 답으로 거절하면 core가 허용하는 경우
새 복구 결정을 제시할 수 있으며 복구하려면 그 별도 결정을 완료해야 합니다. 정리 미확인·오래된 입력·
사용자 편집은 계속 표시하고 우회하지 않습니다. 작업 완료 자체가 검증된 수정은 아닙니다.

대화형 경로는 [#189](https://github.com/casing1/authzest/issues/189)에서 추적합니다. 연결 계층의
오프라인·모의 검사는 실제 Codex·guest 관찰이 아니며 이전 실행 결정을 다시 쓸 권한도 주지 않습니다.

## 기존 결과 가져오기

1. 이미 검토하고 실행한 `owner-read-suggest --file-workflow --runtime-config … --json` 호출의
   최종 stdout JSON을 준비합니다. 계획·상호작용은 stderr에 출력됩니다. `umask 077`로 비공개
   파일에 stdout을 저장합니다. 런타임 준비와 공유·복사본·before·diff·적용·after·복구 결정은
   흐름 계약에서 설명합니다. [소유자 조회 흐름 계약](../development/GENERATED_REPAIR_CONTRACT.md#승인형-복사본-흐름-실행)
2. 대시보드에서 해당 결과 파일을 선택합니다. 가져오기를 거부하면 이전 결과를 지웁니다.
   영어·한국어 선택은 UI 문구를 바꾸며 소스·diff·모델 텍스트는 기록한 내용대로 유지합니다.
3. 요약·단계별 결정·소스·생성 회귀 테스트·정확한 diff·before/after 대조와 복구 필요 상태를
   확인합니다. after 열은 복구 전에 검사한 복사본의 관찰 결과입니다.

저장한 결과를 열 때는 선택한 바이트를 사용하며 모델을 다시 호출할 필요가 없습니다. 현재 소유자 조회
결과는 `kind: "owner-read-suggestion"`, `schema_version: "1.0"`을 사용합니다. 제안만 있는 기록,
거절과 불완전한 기록도 확보된 관찰값과 함께 표시합니다. 선택한 기록에 포함된 경우 before 소스와
정책을 표시합니다. 소스 근거가 없는 이전 소유자 조회 기록은 자료 없음 경고를 표시합니다.

관리하는 보관 노트 사례의 기대 화면은 다음과 같습니다.

| 단계   | 소유자의 보관 노트 | pytest 회귀 테스트     | 의도한 정책 일치 |
| ------ | ------------------ | ---------------------- | ---------------- |
| Before | HTTP 403           | 단언 실패, 종료 코드 1 | 6/7              |
| After  | HTTP 200           | 통과, 종료 코드 0      | 7/7              |

별도의 기대 프로필 일치 개수는 두 단계 모두 7/7일 수 있습니다. before는 관찰한 결함 baseline을
그 단계의 기대 baseline 응답과 비교합니다. 의도한 정책 일치는 관찰 7개 중 목표 정책을 만족하는
개수를 보여 줍니다. 이 수치와 함께 복구 및 복구 필요 상태도 확인합니다. 복구된 복사본은 원래 소스
바이트를 포함합니다. 앞선 after 관찰이 통과했어도 복구가 필요하면 해당 상태를 계속 표시합니다.

`authzest repo-fix … --json`으로 저장한 외부 단일 파일 결과(`kind: "repository-http-fix-result"`,
schema 2.0)도 열 수 있습니다. 기록된 소스와 모델이 작성한 교체 소스로 수정 diff를 다시 만들고
모델의 HTTP PoC를 데이터로 보여 줍니다. 지정 회귀 사례와 검토 사례별 결과가 담긴 수정 전·후 검사,
원본 파일의 적용·복구·복구 필요 상태도 표시합니다. 개인 경로, 계정 정보, runtime 메타데이터, 원시
캡처는 제외합니다. [외부 HTTP 수정](REPOSITORY_HTTP_FIX.md)을 참고하세요.

이전 `codex-generated-file-workflow` 가져오기도 지원합니다. 버전 1.0 기록에는 결합된
`source_evidence`가 포함됩니다. 최상위 버전이 없는 이전 기록은 `legacy-unversioned`로 표시하고
없는 before 소스·선언은 자료 없음으로 유지합니다. 정적 스캔 JSON·등록 템플릿 결과·미리보기·임의
JSON은 각각 별도 형식이며 이 워크플로 가져오기에서 거절합니다.

## 가져오기 경계와 해석

파일 선택은 선택한 바이트를 로컬 API의 `POST /api/results/preview`로 전송합니다. 브라우저와 API는
파일을 512 KiB로 제한합니다. API는 제한된 JSON 형식과 지원 버전을 검사한 뒤 스키마 `1.0`,
provenance `imported-unverified`의 `authzest-workflow-view` 표시 자료를 반환합니다. 파일시스템
경로를 받거나 가져온 기록을 저장하지 않으며 receipt 폴더 조회·명령 실행·모델 호출·패치 적용도
하지 않습니다. 비공개 기록을 호스팅된 viewer에 올리지 마세요.

소스·테스트·diff·설명은 신뢰하지 않는 텍스트로 취급하며 HTML·Markdown 실행 없이 표시합니다.
표시 자료는 로컬 workspace/근거 경로·runtime profile·계정/사용량 metadata·실행 ID를 제외합니다.
이는 범용 비밀정보 제거 도구가 아닙니다. 선택한 소스나 모델 텍스트 자체에도 민감한 정보가 있을 수
있습니다. 원본 JSON과 phase 원본 캡처는 기존 비공개 위치에 남으며 화면이 조회하거나 인증하지 않습니다.

가져오기는 기록에 적힌 주장을 보여 줍니다. 완료된 실행·승인한 결정·테스트 종료값·대조 일치는 보안
판정이나 새 권한이 아니며 실행이 실제로 있었다는 증거도 아닙니다. 불명·미실행·거절·미지원·실패·복구 필요 상태를
구별합니다. Before/after 개수는 관리하는 유한 대조를 뜻하며 생성 테스트 보고는 보조 자료입니다.
화면은 실제 인증·자원 강제·격리·범용 수정 검증을 확립하지 않고, 기록을 열어도 세션을 재개하거나
승인을 다시 쓸 수 없습니다.
