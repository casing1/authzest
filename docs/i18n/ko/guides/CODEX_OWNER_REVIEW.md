# 소유 보고서 정책의 읽기 전용 Codex 검토

[문서 목차](../INDEX.md) · [소유 보고서 정책](OWNER_POLICY.md) · [Codex 설정 fixture](CODEX_FIXTURE.md)

## 범위와 제공 상태

[#75](https://github.com/casing1/authzest/issues/75)는 현재 소스에 `codex-owner-review`를 추가합니다.
유지하는 보고서 접근 예제 하나를 opt-in 읽기 전용 Codex 검토와 구조화된 방어적 테스트 사례
초안에 연결합니다. 공개 alpha.3 바이너리에는 없습니다. 패키지 버전 `0.1.0a3`, scan report
schema `1.2`, 공개 산출물과 별도 `codex-fixture` 흐름은 그대로입니다.

이 단계에는 코드 생성·diff·패치 적용·HTTP endpoint 검사·예제 애플리케이션·endpoint·정책 함수 실행이
없습니다. 유효한 결과는 unknown을 유지하거나 근거 있는 변경이 필요 없다고 답할 수 있으며
억지로 패치를 만들지 않습니다. 일반 저장소 검토와 더 넓은
[#35 흐름](https://github.com/casing1/authzest/issues/35)은 미완료입니다.
오프라인 테스트와 미리보기는 실제 모델 인수 검증 결과가 아닙니다. 별도로 승인받은 실제 시도
1회는 2026-09-24에 수용한 초안 없이 실패했으며 실제 모델 인수 검증은 대기 상태입니다.
아래에 해당 시도와 한계를 기록합니다. 다음 제공자 시도에는 새로운 승인이 필요합니다.

## 공유 전에 미리보기

변경을 포함한 소스 설치본을 사용하세요. `MODEL`은 요청하려는 정확한 모델 ID로 바꿀 자리이며
모델을 자동 선택하지 않습니다. 지원 OS 어디에서든 다음 명령을 사용할 수 있습니다.

```bash
authzest codex-owner-review --model MODEL --preview-only
```

완전한 JSON 미리보기 하나를 출력한 뒤 질문·Codex 실행·계정 접근·네트워크 요청 없이 종료합니다.
Codex나 로그인도 필요하지 않습니다. `--json`·임의 경로·자동 승인 옵션은 없습니다.
미리보기에는 요청·작업 프롬프트·host 지시·출력 스키마·제한과 승인을 연결할 `sharing_id`가
포함됩니다. 이 ID는 요청 ID만이 아닌 전체 공유 내용을 식별합니다. Codex가 자체 harness 맥락을
추가하므로 미리보기가 모델의 전체 맥락을 보여준다는 뜻은 아닙니다.

작업·소스 입력은 다음으로 제한됩니다.

- 소스 식별값과 줄 참조가 있는 패키지 내 관리 snapshot
  `examples/fastapi_owner_policy/main.py`와 `policy.py`. checkout을 읽는 대신 내장 snapshot을 사용합니다.
- 명시적인 소유자 전용 보고서 정책과 신뢰 가정.
- 소스를 import·실행하지 않고 도출한 정적 라우트·`Security` 선언 근거.

개발용 28개 사례 행렬·예상 label·고정 평가 corpus는 모델 입력이 아닙니다. 테스트는 패키지
snapshot과 유지하는 예제가 같은지 확인하지만 명령 자체가 로컬 예제의 변경 여부를 확인한다고
주장하지 않습니다. 다른 저장소 파일·사용자 지정 경로·자격 증명은 작업·소스 입력에 넣지 않습니다.

## 명시적이고 제한된 계정 사용

지원 POSIX 시스템에서는 신뢰하는 Codex **0.153.0** 설치본과 Codex가 관리하는 기존 ChatGPT
로그인을 사용합니다. 이는 호환성 고정이며 현재 설치본이나 최신 Codex가 호환된다는 뜻은
아닙니다. 명령 자체가 Codex 설치·로그인·자격 증명 파일 읽기를 하지 않습니다.

```bash
authzest codex-owner-review --model MODEL --timeout-seconds 120
```

timeout 기본값은 120초이며 120초를 초과할 수 없습니다. 먼저 전체 JSON 미리보기를 표시합니다.
표시된 `share <sharing_id>` 문구를 정확하게 입력해야 제공자 경로를 허용합니다. Enter·다른 답·질문
취소는 아무것도 공유하지 않고 제공자 프로세스를 시작하지 않습니다. 미리보기·거절은 지원 OS
전체에서 가능하지만 실제 제공자 경로는 POSIX 전용입니다. 로그인 성공·정책 기준 승인·이번 기능
구현 허가는 소스 공유 동의를 대신하지 않습니다.

동의 후 공유하는 버전 고정 App Server 전송 계층은 애플리케이션이 시작하는 turn을 최대 1개만
허용하며 AuthZest 재시도·모델 fallback·대체를 하지 않습니다. Codex 내부 통신 재시도는 사용량을
소비할 수 있습니다. timeout과 애플리케이션 시도 횟수는 토큰·금액 상한을 보장하지 않으며
사용량을 모르면 unknown으로 유지합니다. 전송 계층은 [설정 fixture 안내](CODEX_FIXTURE.md)의
유효 설정·식별값·도구/맥락·프로토콜 검사를 재사용합니다. 비어 있는 작업 디렉터리에서 시작하고
ChatGPT 인증의 내장 OpenAI 제공자만 받으며 요청/협상한 모델을 확인하고 도구 작업을 거절합니다.
소스 실행·shell 명령·저장소 탐색·HTTP 테스트는 요청한 검토에 포함하지 않습니다. 신뢰하는
로컬 Codex 설치본이 전제이며 신뢰하지 않는 실행 파일의 sandbox를 보장하지 않습니다.

공식 [App Server 문서](https://learn.chatgpt.com/docs/app-server)는 기반 인터페이스를 설명합니다.
AuthZest의 정확한 공유 범위·버전 고정·읽기 전용 결과 계약은 일반 Codex 제한이 아니라 더 좁은
애플리케이션 규칙입니다.

## 2026-09-24 실제 시도

커밋 `c5be74d6e65c7716ab3eff12ce2f0169fd889b2f`의 소스 CLI에서 Codex `0.153.0`, 기존 관리형
ChatGPT 로그인과 정확히 요청한 모델 `gpt-6-astra`로 1회 시도했습니다. 사용자는 공개 소스
snapshot 두 개·정책·정적 근거의 공유, 애플리케이션에서 시작하는 turn 최대 1개와 120초를
별도로 승인했습니다. assistant가 해당 승인 아래 전체 공유 내용을 대조하고 정확한 공유 문구를
입력했습니다. 이는 모델 작성 사례 예상값에 대한 독립적인 사람 검토가 아닙니다.

CLI는 `98828.2639` ms(약 98.8초) 뒤 수용한 초안 없이 `review-failed`, 종료 코드 `1`을
반환했습니다. 반환 모델 식별값·사용량·경고 횟수·재시도 횟수는 `null`/unknown이었습니다.
구체적인 실패 단계와 원인은 의도적으로 숨기므로 이 결과만으로 timeout·인증·quota 실패를
단정할 수 없습니다. `application_turn_attempts=1`은 로컬 시도 횟수이며 서버가 수용한 turn
횟수나 계정 사용량을 입증하지 않습니다.

추가 제공자 시도는 하지 않았습니다. 대상·애플리케이션·정책 함수·생성 코드 실행, HTTP 테스트나
패치 적용도 없었습니다. 실행 직후 기능 worktree와 원래 `main` checkout은 clean 상태였고
유지하는 두 예제 소스 해시는 바뀌지 않았습니다. 실행은 `not-run`, 인가는 `unknown`, 독립
개발용 label은 미검토 상태를 유지합니다. 실패한 시도는 실제 모델 인수 검증·더 넓은 #35·릴리스를
완료하지 않습니다.

1회 시도 승인은 소비되었습니다. 아직 시작하지 않은 다음 제안 작업은 민감한 내용을 숨기는
안전한 실패 단계 진단 설계와 오프라인 테스트이며, 이후 실제 재시도는 새로운 소스 공유·계정
사용 승인 뒤에만 진행합니다. 실패 결과 자체가 자동 재시도를 허용하지 않습니다.

## 결과 해석

대화형 모드는 미리보기·동의 질문 뒤 최종 JSON 결과를 출력합니다. 전체 터미널 출력은 단일
JSON 문서가 아니며 미리보기 문서 하나만 필요하면 `--preview-only`를 사용하세요.

검증을 통과한 초안에는 근거에 연결된 검토 답변과 1–16개의 구조화된 방어적 사례가 있습니다.
각 사례는 principal/report 입력·예상 boolean·이유를 설명하며 실행 가능한 테스트 코드가 아닌
검토용 데이터입니다. host는 스키마·요청/소스 식별값·허용한 근거 참조를 확인하지만 모델의
설명이나 예상값이 옳다고 증명하지 않습니다. 결과는 `draft`, 사례 예상값은 모델 작성·미검토,
`execution_status`는 `not-run`, `authorization_status`는 `unknown`을 유지합니다.

관리자는 2026-09-24에 인증된 신원·정확한 `reports:read` scope·소유자 일치를 모두 요구하고
관리자 예외 없이 정보가 없으면 거절하는 정책 기준을 승인했습니다. assistant가 작성한 개발용
정답 label 28개나 향후 모델 작성 사례까지 독립적으로 승인한 것은 아닙니다. 예제 인증은
의도적인 미설정·기본 거절 상태를 유지합니다. 소스에 연결된 검토가 실제 인증을 구현하거나
endpoint 인가를 입증하지 않습니다.

| 결과                        | 종료  | 의미                                             |
| --------------------------- | ----- | ------------------------------------------------ |
| 미리보기 또는 `draft-ready` | `0`   | 미리보기/결과 처리가 완료됐으며 보안 통과는 아님 |
| 공유 질문에서 거절·EOF·취소 | `0`   | `not-shared`; 제공자 프로세스 없음               |
| 잘못된 명령 설정            | `2`   | 입력 수정 필요; 검토 성공 아님                   |
| 제공자 또는 응답 검증 실패  | `1`   | 민감한 내용을 제거한 실패; 수용한 초안 없음      |
| 제공자 요청 중 중단         | `130` | 취소됨; 앞서 소비한 계정 사용량은 모를 수 있음   |

기본 `scan`·오프라인 평가 label·기존 fixture 실행 허용 목록은 그대로입니다. 이 명령의 승인
token으로 패치를 적용하거나 테스트를 실행할 수 없습니다. 향후 패치·검증 흐름에는 별도로
검토한 설계와 구분된 사용자 결정이 필요합니다.
