## 범위 — 2026-11-12 KST

[#152](https://github.com/casing1/authzest/issues/152)의 또 다른 부분 단계입니다.
관리형 relay codec은 고정 합성 사례의 응답 사실을 제한된 크기로 읽습니다. **활성 엔진 어댑터가
아닙니다.** 기본 소켓 구현·실행형 모듈 진입점·CLI/API/UI 연결·Docker 확인/빌드/pull·생성 코드
import/실행·제공자 호출·파일 적용/복구는 없습니다. 실행기·세션 런타임도 비활성으로 유지하며
#152는 열린 상태입니다.

[stdlib 전용 relay 모듈](../../../../src/authzest/runner/_generated_repair_http.py)에는 고정 요청 입력과
프로토콜·수집 로직만 있습니다. AuthZest·생성 애플리케이션·테스트·관리형 정답 본문/상태·노출 표식을
import하지 않습니다. 별도 [호스트 전용 bridge](../../../../src/authzest/runner/_generated_repair_relay.py)가
요청 투영을 현재 대조군과 비교한 뒤 완전한 전달 사실만 대조합니다. 향후 relay 이미지에 호스트
bridge·대조 정답을 게스트 입력으로 포함하면 안 됩니다.

## 고정 요청 입력과 호스트 판정

relay는 순서와 ID가 고정된 GET 21개를 소유합니다. 소유자/타인, 누락/빈/미등록 demo actor,
없는 문서, 양쪽의 내 문서 → 타인 문서 → 내 문서 순서입니다. ID·경로·actor 헤더는 요청 입력이며
응답 정답이 아닙니다. 호스트는 요청 입력과 현재 대조군 사이의 변경을 거절합니다. 호출자가 선택하는
demo actor는 **인증이 아닙니다**.

요청 바이트에는 고정 `127.0.0.1`·포트 `8765`, `Connection: close`, identity encoding을 사용합니다.
호출자가 URL·호스트·포트·메서드·프록시/설정·리다이렉트·압축 해제·의존성을 선택하지 않습니다.
요청마다 새 전달 스트림을 사용하며 향후 서버 상태는 독립 A 애플리케이션 안에서만 유지됩니다.
생성 테스트 T의 상태를 A/B로 전달하지 않습니다.

스트림 factory와 동기 시계는 명시적인 **신뢰 Python 구성요소**입니다. factory에 고정 대상과
남은 timeout을 전달하지만, 이를 무시하거나 다른 효과를 일으키는 것을 이 interface가 막지는
못합니다. sandbox·실제 소켓 어댑터·네트워크 격리 증명이 아닙니다. 테스트는 직접 유지하는
인메모리 스트림만 사용합니다.

## 의도적으로 좁은 HTTP 지원

파서는 HTTP/1.1·단일 정규 십진수 `Content-Length`·ASCII 응답 헤더·제한된 원시 본문만
지원합니다. 범용 HTTP 클라이언트나 완전한 표준 구현이 아닙니다. framing 기준은
[RFC 9112 §6.3](https://www.rfc-editor.org/rfc/rfc9112.html#section-6.3)이며 고정 fixture 지원 범위에서
추측하지 않도록 유효한 HTTP 형식 일부도 의도적으로 거절합니다.

| 경계      | 한계 / 거절                                                                         |
| --------- | ----------------------------------------------------------------------------------- |
| 상태 줄   | CRLF 포함 512바이트; 정보/upgrade·본문 없는 204/304 미지원                          |
| 헤더      | 최대 32개; 마지막 CRLF를 포함한 원시·표현 헤더 블록 각각 최대 4KiB                  |
| 본문      | 최대 8KiB; base64로 보존하며 실행·압축 해제하지 않음                                |
| Framing   | Content-Length 하나; transfer coding/chunking·중복/쉼표/누락 길이·구식 folding 거절 |
| 완료      | 정확한 본문 길이와 EOF; 잘림·추가 응답 바이트 거절                                  |
| 전체 수집 | wire 입력·수신 호출·직렬화한 완전/부분 자료를 제한하며 각 데이터 예산 최대 256KiB   |

리다이렉트 상태는 전달 데이터로 기록할 뿐 따라가지 않습니다. 미지원 content coding·비ASCII 헤더·
제어문자·잘못되거나 초과한 framing은 거절합니다. 대상 로그를 응답 사실 채널에 섞지 않으며
호스트 출력 제한과 검증도 독립적으로 유지합니다.

## 만료·부분 결과·정리

수집은 요청·조각마다 새 예산을 만들지 않고 남은 최대 40초의 호출자 **원래 절대 단계 마감**을
소비합니다. 협력하는 factory·스트림 동작 전후와 완전 결과 반환 전에 같은 유한·비역행 시계를
확인합니다. 잘못되거나 역행한 시계·정확한 만료가 수집 성공이 될 수 없습니다.

정상·프로토콜/I/O 실패·시간 초과·취소에 스트림을 닫습니다. 부분 사실·최초 실패와 닫기 실패를
따로 보존합니다. 스트림 닫힘이 컨테이너 종료·제거를 뜻하지 않습니다. 차단·악성 Python 구성요소를
강제 중단하지 못하며 파일시스템·daemon·kernel 전체 시간 보장이 아닙니다.

외부 T/A/B 공유 단계·시작/정리 예산, 누적 stdout/stderr 상한, 정지 생성 검사, staging 식별자,
제한된 프로세스 출력 연결·영속 증거는 운영 어댑터에 남아 있습니다. 이 helper가 새 단계 시간을
부여하거나 로컬 엔진을 검증·Docker 자원을 강제하지 않습니다. 직렬화 크기 제한은 실제 런타임
강제의 측정 결과가 아닙니다.

## 전달 사실은 실행 권한이 아님

호스트 bridge는 현재 고정 순서의 21개 사실을 모두 포함하는 완전하고 제한된 수집만 받습니다.
호출자가 명시한 before/after 후보·현재 대조군을 연결한 뒤 기존 데이터 전용 비교기를 호출합니다.
부분·오류·재정렬·중복·오래된 자료·닫기 실패는 완전한 관찰 세트로 수용하지 않습니다.
가져온 데이터는 계속 호출자 제공·미검증입니다.

스크립트로 만든 before/after 정답 모양이 일치해도 실행 `not-established`, 인가 `unknown`,
`verified_fix: false`입니다. 세션 before 근거·소스 diff 수용·적용/복구 권한·제공자 출처를 만들지
못합니다. 생성 pytest 보고는 신뢰할 수 없는 보조 데이터이며 relay에 넣지 않습니다.

실제 설치형 흐름에는 검토한 로컬 엔진/이미지, 이미지 소유 서버/테스트 launcher, 고정 실제 소켓
진입점, 유효 설정·파일/staging 결합, 수집/영속/게스트 정리 통합·별도 런타임 수용 검증이 남아
있습니다. 이번 오프라인 기반을 과목 완료·릴리스·실제 PoC/수정 관찰로 표시하지 않습니다.
