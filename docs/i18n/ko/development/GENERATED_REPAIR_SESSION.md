# 생성 수정 세션 — 오프라인 결정과 복사만 지원

[문서 목차](../INDEX.md) · [비공개 파일 기반](GENERATED_REPAIR_WORKSPACE.md) ·
[검증 기반](GENERATED_REPAIR_VERIFICATION.md)

## 범위 — 2026-11-10 KST

[#152](https://github.com/casing1/authzest/issues/152)의 후속 오프라인 부분 구현입니다.
내부 세션은 새 로컬 결정을 **복사본 생성**과 **비활성 before 검사 준비**에만 연결합니다.
CLI·공개 API·브라우저 승인 화면과 연결하지 않습니다. 런타임 실행기·엔진 검사·이미지·생성 Python
실행·새 제공자 호출도 추가하지 않습니다. #152는 열려 있고 PoC 재현이나 독립 수정 검증은 미완료입니다.

앞선 파일 도우미는 관리형 테스트에서 비활성 바이트를 적용·복구할 수 있습니다. 그러나 이번 세션에는
**apply·restore 메서드가 없습니다**. 수용한 before 근거, 런타임 증거 가져오기, 실행기 주입 경로도
없습니다. 전달받은 HTTP 사실의 일치, 생성 테스트 보고, 내보낸 기록이나 위조한 ready 결과로 후속
단계를 열 수 없습니다.

## 내부 API와 신뢰

[`_generated_repair_session.py`](../../../../src/authzest/runner/_generated_repair_session.py)는 다음을 제공합니다.

- `GeneratedRepairSession(preview, clock=...)`: 정확한 현재 미리보기를 검증하고 새 프로세스 내
  식별자로 시작합니다. 생성자에서 파일시스템·런타임 작업을 하지 않습니다.
- `prepare("copy")`·`prepare("before")`: 현재 허용 단계의 전체 내용 결합 계획을 만들며 실행 권한은 아닙니다.
- `decide(stage, choice, plan_id=..., lifetime_seconds=...)`: 정확한 현재 계획에 한 번만 최종 로컬 선택
  `approved`·`declined`·`cancelled`를 기록합니다.
- `create_copy()`: 현재 전제·독립 결정이 허용할 때만 복사 시도 한 번을 소비하고 기존 도우미로 새 비공개
  복사본을 만듭니다.
- `prepare_before()`: 자체 시도를 소비하고 기본 비활성 readiness 경로만 확인합니다.
- `result()`·`close()`: 제한된 과거 상태 기록을 내보내거나 파일을 보존하면서 descriptor를 닫습니다.
  가져온 기록으로 시작하거나 재시작·재개하는 API는 없습니다.

Python 호출자와 시계 callback은 신뢰한 코드입니다. 사람의 인증·제공자 출처·OS sandbox를 보장하지
않습니다. 복사 생성의 비공개 `_parent` 인자는 pytest 임시 부모 경로 전용이며 아티팩트가 선택하는
목적지나 지원하는 사용자 옵션이 아닙니다. 리포트/패키지 버전·의존성·Codex pin·기존 등록
흐름은 바꾸지 않습니다.

## 계획과 원래 만료 시각

복사 계획은 전체 현재 소스/테스트와 호스트 계산 diff 두 개, 고정 경로, 시나리오/대조군/recipe,
새 세션 식별자와 세대를 결합합니다. 복사 때 테스트를 만드는 것과 아직 허용하지 않는 후속 소스
교체를 구분합니다. 복사 전 파일시스템 식별자는 명시적으로 미관찰 상태입니다.

생성 확인 후 before 계획은 현재 검사한 root/tests 디렉터리 manifest와 journal을 포함한 관리 파일
여섯 개의 식별자/해시, 같은 현재 아티팩트를 결합합니다. 전달받은 manifest JSON이 아닌 활성
도우미의 확인한 상태에서 만듭니다. 바이트 변경·같은 바이트의 inode 교체·snapshot/journal 변경·
root/하위 디렉터리 교체는 승인을 조용히 다시 연결하지 않고 기존 계획을 무효로 만듭니다.

계획은 최초 생성 시각과 그로부터 최대 300초인 원래 만료 시각을 유지합니다. 재준비로 갱신할 수
없습니다. 나중 결정에는 별도 결정 시각을 기록하고 만료를 줄일 수만 있습니다. 선택은 최종적이며
거절·만료·소비 후 대체 승인은 없습니다. 만료 시각과 정확히 같아도 만료입니다.

monotonic 시계는 유한·음이 아닌·역행하지 않는 값이어야 하고 요청 기간도 고정 상한 내에서 표현할
수 있어야 합니다. Boolean·NaN·무한대·역행·표현 불가 값은 유효하지 않습니다. 검증/읽기에도 시간이
걸리므로 이후와 복사 할당 직전에 시각을 재확인합니다. 파일시스템 작업의 보편적인 시간 상한은 아닙니다.

## 일회성 시도와 정확한 효과 상태

복사와 before 준비는 각각 별도 일회성 시도입니다. 계획/결정 없음·대기·거절·취소·만료여도 동작 호출은
dispatch 전에 시도를 소비합니다. 먼저 잘못 실행했다고 나중 재시도를 예약하지 않습니다. 잘못된 결정
입력이 기존 대기 선택을 바꾸면 안 됩니다. 상태를 바꾸는 재진입은 거절하고 중첩 호출이 바깥 호출의
busy guard를 해제하지 못하게 합니다.

복사 기준은 정확한 before 앱과 제안 테스트, 불변 snapshot, 호스트 journal입니다. 재읽기/sync가 확인된
경우에만 복사 확인 상태입니다. 부분 초기화는 알려진 경로·단계·파일 생성 상태·불확실성을 남기며 취소를
무쓰기 상태로 바꾸지 않습니다. 자동 재시도·삭제·강제 rollback·기존 디렉터리 재생성은 없습니다.

`prepare_before()`는 준비와 실제 실행을 구분합니다. 정상 준비여도 기본 상태는 not ready이며 실제 실행은
미수행, 런타임 기준은 미확립, 소스 적용/복구는 미수행, 접근통제 보장은 unknown, `verified_fix`는 false입니다.
생성 테스트를 import·compile·수집·실행하지 않습니다.

후속 `source-diff`·`source-apply`·`after`·`restore`는 `runtime-not-implemented`로 거절합니다.
이는 아직 미완료인 실행 경계를 뜻하며 host pytest나 기존 고정 정책 worker로 대체하지 않습니다.

## 기록·종료와 다음 경계

`result()`는 제한된 비인증 과거 상태 기록입니다. 세션이 기록한 사실을 보여줄 뿐 파일을 새로 검사하거나
동의를 인증하거나 결정을 되살리지 않습니다. 파일 계층 journal도 별도 작업 기록이지 영속 세션 승인
저장소가 아닙니다. 종료는 복사본과 근거를 보존하며 닫힌 세션은 추가 동작을 승인할 수 없습니다.

관리형 테스트는 직접 작성한 비활성 문자열·임시 파일·모의 시계를 사용합니다. 원래 만료 보존·거절/만료/
재사용·파일 식별자 변경·부분 생성·취소·재진입·런타임/소스 쓰기 권한을 얻을 수 없음을 확인합니다.
실제 모델 응답·생성 코드 실행·설치 후보 전체 흐름 수용 검증이 아닙니다.

다음에는 검토한 컨테이너/relay 생명주기가 실제 캡처 파일 관찰과 정리 확인을 제공해야 적용 경계를 연결할
수 있습니다. 후속 소스 쓰기는 commit 직전 최종 신뢰 시각 재검사가 필요합니다. 기존 도우미의 앞선 guard와
그 뒤 journal I/O만으로 보장되지 않습니다. 독립 대조와 생성 보고는 계속 구분하며 실제 운영 실행·정확한
후보 수용·로컬 읽기 전용 UI·릴리스는 별도 조건입니다.
