## 현재 릴리스 범위 — 2026-11-24 KST

확정한 [0.1.0 범위](0.1.0-SCOPE.md)는 명시적으로 선택한 자체 완결형 외부 FastAPI 한 파일,
GET 객체 소유권과 명시적인 정책을 대상으로 합니다. 모델이 새로 작성한 제한된 HTTP PoC 데이터와
수정 소스, 호스트에 둔 독립 기대값과 A/B 변경 전후 관찰을 목표로 하며 이 외부 모드의 생성
Python/pytest 실행은 후순위입니다. 익명 접근 정책 검사는 일반 인증의 안전성을 입증하지 않습니다. 최종 승인한 원본
적용·백업·동시 편집 거부·복구는 계속 필수입니다. 최초 실제 지원은 macOS arm64의 Python 소스
설치와 Docker Desktop이며 CLI 조작과 외부 저장 결과 GUI 열람을 목표로 합니다.

이는 범위 결정이지 구현된 HTTP 전용 런타임 권한이나 제품 수용이 아닙니다. 외부 런타임·CLI 연결과
원본 쓰기는 미완료입니다. 아래 전달한 S1/S2/S3 계약과 T/A/B 기반의 정확한 동작·식별자를
보존합니다. 이전 T/pytest와 외부 활성 GUI 완료 계획은 더 넓은 후속 작업으로 남기며 현재 릴리스의
필수 조건으로 삼지 않습니다. 별도 HTTP 제안·사례·이미지와
[비공개 파일/checkpoint API](../reference/REPOSITORY_HTTP_FILES.md)를 전달했으며 T 결과를 꾸미거나
과거 저장 자료를 조용히 수용하지 않습니다. 비공개 파일 결정이 모델·guest 실행·원본 쓰기·위험 수용·
발행을 승인하지 않습니다.

## 현재 상태와 이번 제공 범위

현재 `repo-suggest` 명령은 명시적으로 선택한 외부 Python 소스, 정책, 문맥을 캡처하고
회귀 테스트 제안, 대체 소스, 호스트가 산출한 diff를 반환합니다. 복사본을 만들거나 프로젝트를
실행하거나 원본 작업 트리를 수정하지는 않습니다. 패키지에 포함된 owner-read GUI와 고정 worker는
계속 별개이며 외부 프로젝트 실행을 대신하는 대체 경로가 아닙니다.

아래 S1은 효과 없는 메타데이터 계약으로 유지합니다. 별도의
[S2 파일 세션 API](../reference/REPOSITORY_FILE_SESSION.md)는 live 원본 캡처와 새 비공개 복사·diff·적용·복구
결정을 구현하고 직접 관리하는 비활성 임시 파일·모의 clock/실패로 검사합니다. CLI/GUI 조작 흐름,
저장 workspace 열기, 대상 실행, 원본 쓰기는 활성화하지 않습니다.
[S3 인터페이스·사례 계약](../reference/REPOSITORY_VERIFICATION.md)은 순수 선언과 제공 자료 비교를
구현합니다. 별도 [런타임 기반](../reference/REPOSITORY_RUNTIME.md)은 봉인 staging·guest 진입점 소스·
제한된 HTTP 처리·정적 생성 자료를 비활성 파일과 가짜 peer로 구현·검사합니다. 아래 실제 이미지·런타임
수용은 미완료입니다. 설계·소스 검토는 구체적인 사례 기대값·런타임
이미지·소스 공유·실행을 승인하지 않습니다.
정식판 발행은 #150–152에 따른 확정 외부 프로젝트 범위 완성까지 계속 보류합니다.
이전 #189 계획의 외부 프로젝트 활성 GUI 작업은 후순위입니다.

## S1: 효과가 없는 복사 계획 계약

`authzest.codex.repository_copy_plan`은 `RepositoryCopyPlan`,
`prepare_repository_copy_plan(request, response)`,
`validate_repository_copy_plan(plan, request, response)`를 제공합니다. 준비 단계는 현재 요청과
응답 전체를 검증합니다. 유효한 `no-change`, `unknown`, `refused` 응답은 `None`을 반환합니다.
`proposed-change`이면 다음을 기록합니다.

- 모델과 설명 필드를 포함한 전체 요청·응답의 정규화된 식별자.
- 각 자료 파일의 역할, 정확한 상대 목적지, 선택한 원본 경로가 있다면 그 경로, UTF-8 바이트 수,
  SHA-256. 정확한 before/after/restore 소스 해시와 호스트가 산출한 diff 해시.
- 레이아웃 버전 `1.0`, 최대 128 KiB의 파일 자료와 별도의 최대 64 KiB 호스트 journal.
- 원본의 생성 테스트 경로는 **미검사**이며 새 루트와 원본 검사가 여전히 필요하고 모든 효과·결정은
  수행하지 않았다는 상태. 계획에는 소스 본문, diff, 절대 루트, 승인이 들어 있지 않습니다.

검증은 제공된 현재 요청·응답으로 전체 계획을 다시 구성하여 정확히 비교합니다. 수정한 메타데이터의
해시를 다시 계산해도 이 비교를 통과할 수 없습니다. 객체 생성이나 저장된 JSON 가져오기는 workspace,
권한, 인증된 provider 출처, 런타임 근거를 부여하지 않습니다. S1은 파일시스템, 네트워크, 프로세스에
접근하지 않습니다. 원본 파일에 미치는 효과에 대한 설명은 이 API에 한정되며 앞선 입력 캡처나 다른
프로세스가 가한 변경을 설명하지 않습니다.

## 제안하는 비공개 레이아웃과 최신 상태 확인

추후 live session은 모드 `0700`의 새 비공개 디렉터리를 만들고 symlink/hardlink 없이 일반 `0600`
파일을 배타적으로 생성합니다.

```text
authzest-repository-<nonce>/
  project/<selected source and Python context paths>
  project/tests/test_authzest_regression.py
  evidence/policy.txt
  evidence/source.before
  evidence/source.after
  evidence/test.txt
  record.json
```

이는 재귀 복제가 아닌 **선택 소스 workspace**입니다. 정책과 복구 snapshot은 앱 트리 밖에 둡니다.
선택하지 않은 `.env`, 자격 증명, 의존성·설정 파일, `conftest.py`, 관련 없는 테스트를 탐색하거나
복사하지 않으며 합성 `__init__.py`를 추가하지 않습니다. 필요한 패키지 초기화 파일은 문맥으로 명시적으로 선택해야 하며 기존 선택 예산을
사용합니다. 필요한 import가 없으면 지원하지 않는 경우로 처리합니다. 선택한 Python 파일은 비어 있어도
되지만 제안 소스와 테스트는 공백만으로 이루어질 수 없습니다. 모든 바이트는 UTF-8입니다.

무엇이든 생성하기 전에 동일 경로와 파일/디렉터리 접두 경로 충돌을 거부합니다. 선택한
`tests/test_authzest_regression.py/child.py`도 이에 포함됩니다. 또한 정규화·대소문자 비구분 파일시스템을
고려하여 정규 대소문자 비구분 별칭(`NFD → casefold → NFD`)을 보수적으로 거부하되 정확한 표기는 유지합니다. 원본 프로젝트의 생성
테스트 경로는 검사한 적이 없습니다. `/dev/null` 테스트 diff는 새 비공개 산출물만을 뜻합니다. 목적지를
배타적으로 생성하여 새 복사본에서 부재를 확인해야 하며 이로써 원본 프로젝트의 부재를 확인할 수는
없습니다.

향후 live-origin 캡처는 최초 로컬 워크플로 검토 시점의 루트·선택 파일 식별자(또는 유지한 descriptor)를
캡처 바이트와 함께 보관하고 복사 직전에 비교해야 합니다. 기존 콘텐츠 전용 loader는 descriptor를
닫습니다. 저장된 요청·계획·`RepositoryInput`으로는 이 식별자 기준을 복원하거나 이전 캡처 이후의
동일성을 입증할 수 없습니다.
복사 전에 no-follow 제한 loader로 선택한 원본 입력을 모두 다시 캡처하고 정확한 바이트와 현재
로컬 루트·파일 식별자를 비교하여 바뀐 입력을 거부합니다. 새 비공개 루트, 파일, 불변 근거를 현재
프로세스의 live handle에 결합합니다. 콘텐츠 해시나 기존 `RepositoryInput.root`만으로는 이 live 결합이
성립하지 않습니다. 적대적인 동시 쓰기 주체에 대한 원자적 snapshot을 보장하지 않습니다. 시작·복사가
부분적으로 실패하면 관찰한 파일을 보존하고 실패를 기록합니다. 이후 저장된 JSON을 열어 이 파일들을
다시 수용하지 않습니다.

복사 후에는 비공개 식별자와 동결된 바이트를 확인합니다. **원본**의 편집이 독립된 비공개 복사본의
복구를 막아서는 안 됩니다. 비공개 소스, 테스트, snapshot, journal의 편집은 덮어쓰지 않고 쓰기를
차단합니다. live handle은 마지막으로 자체 commit한 journal 바이트·식별자·상태를 보관하고 영속
다시 읽기가 성공한 뒤에만 갱신합니다. 저장된 JSON에서 이 권한을 복원하지 않습니다. 불확실한 journal
실패는 recovery-required로 보고하며 자동 복구하지 않습니다.
원본 프로젝트 적용에는 아래의 별도 최신 상태 확인 gate를 둡니다.

## 현재 결정과 복구 가능한 쓰기

제안하는 진행 순서는 런타임·사례 검토 → 공유 → 복사 → before → 정확한 diff 수용 → 비공개 적용 →
after → 비공개 복구입니다. 각 변경·실행에는 현재의 전체 미리보기, 별도 live-session token, 일회용
결정, 최초 단조 시계 기준 최대 300초 만료가 필요합니다. 오래된 token, 재사용, 가져온 결정, 자동 승인,
기한 연장, 저장 기록을 통한 다시 열기·재개를 거부합니다. 콘텐츠 식별자는 산출물을 식별할 뿐 결정이
아닙니다.

쓰기 전에는 식별자와 정확한 예상 바이트를 재검증하고 의도를 영속 기록한 뒤, commit 직전에 live
결정·만료를 다시 확인합니다. 배타적 임시 파일과 원자적 교체를 사용하고 목적지를 다시 읽은 다음
완료를 기록합니다. 범위는 현재의 단일 소스뿐입니다. 정확한 생성 테스트와 근거는 보존합니다. 지원하지
않는 영속성·메타데이터 동작은 거부합니다. commit·다시 읽기·journal 단계의 실패는 실제로 확인된 상태를
보존하고 이후 일반 변경을 차단하며 필요하면 `recovery-required`를 보고합니다. rename을 시도했다는
이유만으로 rollback을 주장하지 않습니다.

복구는 현재 비공개 소스가 수용한 after 바이트와 같은지, before snapshot이 최초 캡처한 before 바이트와
같은지 각각 확인한 뒤 해당 소스만 before로 교체합니다.
사용자 편집, 테스트 산출물, 근거, 과거 after 결과를 지우지 않습니다. 최종 출력은 현재 소스 바이트와
과거의 after 통과 관찰을 구분합니다. 런타임 실패와 파일 상태는 별개입니다. after 검사에 실패했더라도
식별자와 실제 바이트가 확인된 경우에만 별도 검토한 복구를 허용할 수 있습니다. 알 수 없는 상태를
성공으로 바꾸지 않습니다.

## 제안하는 외부 런타임 인터페이스

이 절은 이전 T/A/B 설계와 전달한 기반의 계약을 보존합니다. 생성 테스트·pytest 요건은 확정한
HTTP 전용 릴리스 목표가 아닙니다. 위의 별도 HTTP 소스 API는 전달했지만 직접 실행·조작 흐름
연결은 미완료입니다. 격리·최신 상태·근거 보호는 계속 설계 제약으로 유지합니다.

외부 Python은 신뢰하지 않습니다. 고정된 소유 worker와 기존 registry는 유지하고 패키지 worker가
임의 경로를 받아들이게 하는 대신 별도의 버전이 있는 런타임 계약을 만듭니다. 호스트에서 대상 코드를
import하거나 수집하거나 설치하지 않습니다.

첫 런타임은 명시적으로 선택한 import, GET 라우트, 크기가 제한된 JSON 응답을 사용하는 독립적인
in-memory FastAPI 앱을 지원합니다. 선택한 Python 파일 중 `entry_source`, `.` 또는 `src` import root,
일반 앱 속성 식별자(기본값 `app`)를 검토합니다. 모듈 경로는 도출하고 factory는 거부하며 진입점을
탐색하지 않습니다. Lifespan은 비활성화합니다. 데이터베이스·서비스, 프로젝트 의존성 설치, 외부 identity
provider, 실제 자격 증명은 지원하지 않습니다. 필요한 import, fixture, 설정 요건을 충족할 수 없으면
합성 대체 경로 없이 unsupported로 중단합니다.

현재 제안 스키마 `1.0`은 실행 가능한 fixture를 보장하지 않습니다. 별도의 순수 `1.1` 요청 계약은
이제 모델에 보이는 `test_interface`를 정의합니다. 여기에는 명시적
진입 소스·import root·앱 속성, 신뢰하는 `client` fixture, lifespan 비활성화를 담습니다. 전체 prompt·요청
식별자에 결합하고 독립적인 사례 기대값은 호스트에 비공개로 둡니다. 현재 `1.0`의 제안 전용 기본값을
유지하며 저장된 `1.0` 결과를 쓰기·실행 권한으로 바꾸지 않습니다. AST가 유효한 생성 Python만으로는
안전하거나 실행 가능한 코드라는 근거가 되지 않습니다.

각 단계에서 현재 비공개 바이트를 별도로 봉인하고 검증한 입력으로 정확히 stage합니다. live workspace를
mount하지 않습니다. 기존 T/A/B 분리를 따라 **별도 guest 세 개**를 사용합니다.

| Guest | 입력과 목적                                                                    | 권위                                               |
| ----- | ------------------------------------------------------------------------------ | -------------------------------------------------- |
| T     | 생성 테스트와 선택 소스. 신뢰하는 bootstrap이 인증 override 없이 `client` 제공 | Pytest 출력과 종료 상태는 신뢰하지 않는 보조 관찰  |
| A     | 선택 소스만. 신뢰하는 launcher가 Uvicorn으로 명시적 앱 시작                    | 대상 응답은 신뢰하지 않음                          |
| B     | 신뢰하는 고정 HTTP observer와 요청 일정. 소스·테스트·기대 정답 없음            | 호스트가 제한된 캡처 응답을 검증하고 기대값과 비교 |

T와 A에는 네트워크가 없습니다. B는 A의 네트워크 namespace에만 참여하며 PID·mount namespace에는
참여하지 않고 호스트 port를 노출하지 않습니다. 각각 읽기 전용 root, 제거된 capability,
no-new-privileges, 제한된 임시 저장소를 사용하며 Docker socket, 호스트 환경, 자격 증명을 제공하지
않습니다. T는 격리된 생성 테스트 경로에서 명시적으로 수집하며 plugin autoload·config·conftest 탐색을
끄고 신뢰하는 import bootstrap을 사용합니다. 이러한 조치를 해도 대상 import는 여전히 신뢰하지
않습니다. T는 권위 있는 독립 대조 기록을 제공할 수 없습니다. B는 대상 코드를 import하지 않으며
호스트가 기대 정답을 보유합니다.

제안하는 단계 제한은 시작·요청·완료를 함께 묶은 40초 기한과 정리용 10초입니다. guest나 요청마다
기한을 다시 시작하지 않습니다. 각 guest는 최대 1 CPU, 512 MiB 메모리, 64 PID, 32 MiB tmpfs를 사용하고,
캡처 출력 합계는 최대 256 KiB입니다. 정확한 이미지·launcher·codec·stage한 바이트 식별자, 응답 제한,
종료 상태, 모든 guest의 정리를 강제하고 기록합니다. 자동 재시도나 단계 재개는 없습니다. 호스트
파일시스템·Engine 호출에는 전체 작업의 엄격한 실시간 상한이 없으며 이 통제는 탈출 불가능한 격리가
아닙니다. 구체적인 이미지는 여전히 검토가 필요합니다.

## 독립 사례와 정확한 before/after gate

사례 정책과 모델 출력·독립 기대값의 분리는 계속 적용합니다. 아래 T 전용 assertion/pytest 조건은
이전 설계만 설명합니다. 확정한 HTTP 전용 경로는 검토한 호스트 기대값과 제한된 HTTP 관찰로
재현·수정 효과를 확인해야 하며 생성 pytest를 실행하거나 통과했다고 주장하지 않습니다.

사람이 검토한 사례를 4–8개 유지하며 각각 GET을 최대 한 번 수행하고 지정된 회귀 사례를 하나 둡니다.
작성 주체, 정책 가정, 역할 설정, 예상 **before와 after** 관찰을 모델 출력과 별도로 기록합니다.
해당하는 경우 인증된 정상 사용, 비소유자 거부, 익명 거부를 다루고 명시적 공개 의도 또는 검토된
해당 없음 사유도 포함합니다. AST 선언만으로는 이러한 정책 의도를 확정할 수 없습니다. 검토 문자열이나
사례 JSON은 인증된 사람의 승인이 아닙니다.

초기 요청은 상대 경로와 제한된 합성 allowlist header를 사용하며 Host, Authorization, Cookie,
proxy·framing header와 실제 자격 증명은 제외합니다. redirect, 재시도, 절대 URL, callback·정규식 matcher,
임의 요청 script는 허용하지 않습니다. 정확한 상태와 타입이 지정된 JSON·빈 본문 기대값을 정의하며,
중복 key·유한하지 않은 수의 엄격한 거부, HTTP framing·fragment 제한, 응답 바이트 제한을 적용합니다.
observer에는 요청 일정만 전달하고 기대값은 호스트에 둡니다.

before 수용에는 검토된 before 관찰과의 정확한 일치, 원하는 정책에 대한 의미 있는 지정 불일치,
그에 대응하는 생성 assertion 실패가 필요합니다. 수집·설정 실패, 테스트 0개, skip/xfail, HTTP 500,
timeout, 잘못된 출력은 접근통제 결함의 재현이 아닙니다. T의 실패는 보조 정보일 뿐이며 독립적인 호스트
비교가 검토된 관찰을 확립해야 합니다. after 수용에는 생성 회귀 테스트 통과, 의도한 모든 독립 대조
항목의 일치, 모든 guest의 정리가 필요합니다. 대상·테스트가 자신의 동작을 조작할 수 있습니다. 유한한
관찰은 검토한 사례를 뒷받침하며 일반적인 접근통제 보장이나 임의 저장소의 정확성을 보장하지 않습니다.

## 원본 프로젝트 수정은 계속 완료 조건

비공개 복사본의 after 단계가 성공해도 원본 저장소가 수정된 것은 아닙니다. 제품 목표에는 검증한 소스
변경을 원본 프로젝트에 적용하겠다는 사용자의 명시적인 최종 결정이 포함됩니다. 이 작업을 #152와
#150에 계속 표시하고 비공개 복사본 복구만으로 완료 처리하지 않습니다.

원본 적용을 활성화하기 전에 구체적인 설계를 별도로 검토합니다. 원본 root와 **선택한 모든**
바이트·식별자를 재확인하고 통과한 복사본과 정확한 diff에 결합하며 현재 단일 파일 원본 쓰기를
미리 보여줍니다. 원본 메타데이터·backup·영속 의도를 보존하고 동시 편집을 거부하며 이후 사용자
변경을 덮어쓰지 않는 명시적 원본 복구·회복을 구현합니다. 원본에 새 테스트를 배치하려면 별도로
검사한 부재·충돌 결정이 필요합니다. S1 계획은 그 경로를 검사하지 않으며 어느 쓰기도 승인하지
않습니다. 원본 상태가 달라져도 비공개 복구는 독립적으로 가능합니다. 이번 단계에는 원본 쓰기 API를
구현하지 않습니다.

## 점진적 제공

이 목록은 이전 단계와 전달한 소스 사실을 보존합니다. 현재 과목 목표는 위 HTTP 전용 CLI 흐름과
저장 결과 열람입니다. T 실행과 외부 활성 GUI 연결은 후순위이며 기반 완료만으로 활성화되지 않습니다.

1. **S1:** 효과 없는 메타데이터 계획, 순수 변조·경로·예산 테스트와 영한 설계를 #203으로 전달.
2. **S2, 현재 파일 API:** 직접 관리하는 비활성 임시 파일·모의 clock/실패 peer로 새 비공개 workspace와
   정확한 적용·복구를 구현. 런타임·조작 흐름 경계는 없으며 실제 프로젝트 동작과 설치형 실제 수용은
   미완료로 유지. #204와 소스 API 참조를 확인.
3. **S3:** 버전이 있는 순수 테스트 인터페이스·독립 사례 codec·제공 자료 비교를 #206에서 구현.
   #208은 봉인 staging·별도 T/A/B 소스·raw HTTP 처리·pin 정적 profile을 가짜 peer로 구현·검사.
   실제 외부 실행 전 이미지·직접 반환한 live 결과의 호스트 조정·런타임 수용은 미완료.
   현재 v1.0 전송·파일 API는 새 v1.1 타입을 받지 않음.
4. **S4:** 명시적 CLI 파일 workflow와 설치판에서 별도 범위의 실제 외부 before/after/복구 수용.
   제안 전용 기본값을 유지하고 읽기 쉬운 결과·전체 JSON 결과 제공.
5. **S5:** 외부 저장소를 수정하는 제품이라고 주장하기 전에, 새로 확인한 원본 입력과 명시적인 현재
   사용자 결정을 사용하는 원본 프로젝트 최종 적용·복구 검토.
6. **S6:** 공통 엔진 위의 GUI, 설치판 종단간 근거, 현재 후보 릴리스 검토. 패키지 시연, 정적 외부 scan,
   외부 live 수용은 계속 구분.

각 단계는 실패·unsupported 결과, 근거의 한계, 영한 문서, 정확한 head의 CI·리뷰 제공을 유지해야
합니다. 순수 계획이나 fake process 결과로 이후 live gate를 충족할 수는 없습니다.
