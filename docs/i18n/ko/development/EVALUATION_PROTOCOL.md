# 평가 프로토콜과 v1 참고 정답 스냅샷

[문서 목차](../INDEX.md) · [English](../../../development/EVALUATION_PROTOCOL.md) · 한국어

이 문서는 [#84](https://github.com/casing1/authzest/issues/84)의 오프라인 참고 정답 준비 단계이며
실제 비교용 전체 벤치마크 동결·모델 평가 결과·수용 기준 완료가 아닙니다. 직접 관리하는 합성
시나리오 7개, 개발용 3개·평가 예약용 4개이며 사례마다 질문 3개, 총 21개입니다. 11월 6일 사용자는
현재 정확한 정답 21개를 수용하는지 묻는 질문에 직접 확정 답변을 했습니다. 이를
`accepted-current-reference-values`, 출처 `direct-user-chat-confirmation`, 기록 주체
`recorded_by` assistant로 기록합니다. 소스·참고 정답의 작성 주체는 사람이 아닌 assistant로 유지합니다.

앞서 사용자가 공개 의도 대조 항목을 요청했고 준비 단계에서 `status-probe-context`를 예약 평가에
배치했으며 기존 시나리오 6개·각 분할·정답 제안 18개는 바꾸지 않았습니다. 이전 긍정적인 반응과
준비 PR 병합은 당시 정답 승인이 아니었으며, 11월 6일 직접 확인을 새로운 정답 값 결정으로 기록하고
과거 승인을 소급하지 않습니다. v1은 소스·질문·분할·정답 값·채점 수학만 고정합니다. 독립 검토 증명과
모든 소스/이유/인용을 확인했다는 증명은 수집하지 않았으며 `independent_review_attested`는 false입니다.
실제 프롬프트·모델/설정·반복 예산은 미고정, `live_benchmark_ready`는 false이고 #84의 체크 항목
7개도 모두 미완료입니다.

[과거 자료 목록](EVALUATION_INVENTORY.md)의 기존 파일·식별자·승인은 변경하지 않습니다.
새 참고 정답셋은 과거 사례의 추가 관찰이 아닙니다. 실제 시험이나 모델 품질을 주장하기 전에
[모델 전략](MODEL_STRATEGY.md)을 따릅니다.

## 후보 자료와 읽기 전용 사전 검사

소스 checkout 전용 파일은 `tests/fixtures/evaluation_candidate/draft/tasks.json`과
`references.json`입니다. 작업 파일은 가상 소스 경로와 소스 텍스트를 실행하지 않는 JSON 데이터로
포함하며 실행용 fixture 모듈이 아닙니다. 참고 정답 파일은 평가자 전용이며 개별 검토를 위한 예상
정답·이유·인용을 포함합니다. 사람이 나중에 검토해도 원래 정답 작성 주체가 사람으로 바뀌지는 않습니다.

Python 3.12 이상으로 저장소 루트에서 실행합니다.

```bash
python scripts/check_evaluation_candidate.py
python scripts/check_evaluation_candidate.py --json
python scripts/check_evaluation_candidate.py --review
python scripts/check_evaluation_candidate.py --review --json
```

기본 출력은 간결한 사전 검사 요약이며 `--json`은 기계가 읽을 수 있는 출력을 선택합니다.
`--review`는 정확한 예상 정답·이유 검토 자료를 추가합니다. 이 자료를 제공자 입력에 넣으면 안 됩니다.
사람용 출력에는 줄 번호·escape를 적용한 가상 소스와 질문을 표시하고, 검토 JSON에는 정답 초안과
연결된 공개 입력도 포함합니다.
성공한 출력도 `draft-not-frozen`·실행하지 않음·실제 호출 시험 0개·벤치마크 준비 미완료를 선언합니다.
기존 검사기는 변경하지 않은 원래 제안 메타데이터를 읽으므로 당시 검토 대기 상태를 의도적으로
유지하며 새 v1 결정 manifest는 읽지 않습니다. 보존한 제안 당시 상태와 현재 정답 값 결정을 혼동하거나
과거에도 승인된 것처럼 이력을 고치지 않습니다. 종료 `0`은 사전 검사 일치이지 올바른 정답·검토 완료·성능·허가·보안이 아닙니다. 종료 `1`은 잘못된
후보 데이터나 검사 실패, 종료 `2`는 잘못된 명령줄 사용을 뜻합니다.

검사기는 엄격한 스키마·읽기 상한·안전한 경로·UTF-8·내용 연결·인용 줄 범위를 확인합니다.
소스 import·정책 실행·제공자 호출·네트워크 사용·패치 적용·승인 부여는 하지 않습니다.
범위 안의 인용도 무관하거나 오해를 줄 수 있습니다. 해시 일치는 의미상 정확성이나 진위 인증이 아니며
편집자가 데이터와 연결 값을 함께 바꾸면 일치시킬 수 있습니다.

공개 입력 식별자는 소스 경로·텍스트, 명시된 정책과 질문을 포함한 canonical JSON 투영을 연결합니다.
바깥 JSON 파일의 원본 바이트 해시가 아닙니다. 바깥 표현의 단순 서식 변경은 식별자를 바꾸지 않지만
포함된 소스 텍스트의 변경은 바꿉니다. 과거 목록 해시·소스 revision·승인 식별자·인증된 검토 기록과
서로 대체하면 안 됩니다.

`public_inputs(root)`는 작업·소스 데이터만 읽어 해당 공개 투영을 반환합니다. 참고 정답·이유·
분할·작성 주체 메타데이터는 제외하며, 사전 검사는 그 뒤 정답을 별도로 읽습니다. 이 분리는 유출
검사이지 구현된 실제 비교 adapter나 동의 절차가 아닙니다.

## 수용한 v1 참고 정답 스냅샷과 오프라인 검사

소스 checkout 전용 스냅샷은
`tests/fixtures/evaluation_reference/v1/{tasks.json,references.json,manifest.json}`입니다.
작업·정답 파일은 수용한 제안 파일의 원본 바이트 복사본이며 원래 검토 대기/작성 주체 메타데이터도
보존합니다. 별도 manifest는 현재 결정·11월 6일 날짜·출처를 `current-21-reference-values-confirmed`로
기록하며 대화 원문은 싣지 않습니다. GitHub 신원 인증·서명·모든 이유/인용 확인을 증명하지 않습니다.
Assistant가 기록한 대화 결정은 도구가 인증한 검토자 신원이나 독립/블라인드 검토가 아닙니다.

Manifest는 소스 revision `ee1b988a11d8ce561f6e155451ef6e40c6a5c318`, 작업/정답을 합친 canonical 후보 식별자
`1a84d57c0ea80d9d4f5bf53c1a1676c08a8a66f8902354fb2424285b12bae938`, 복사한 데이터 파일 두 개와
현재 `scripts/evaluation_metrics.py` 바이트의 원본 해시를 고정합니다. 전체 고정 값은 manifest를
참고합니다. 이 연결은 일치 확인이지 진위나 의미상 정답의 증명이 아닙니다. v1은 바꾸지 않는 버전
스냅샷으로 다루며 데이터·수학이 바뀌면 v1 해시를 갱신하지 않고 새로 검토한 v2가 필요합니다.

```bash
python -m scripts.evaluate_reference
python -m scripts.evaluate_reference --json
python -m scripts.evaluate_reference --control
python -m scripts.evaluate_reference --control --json
```

기본 출력은 읽기 전용 고정 정답 사전 검사이지 실제 시험이나 점수가 아닙니다. `--control`은 정답을
읽기 전에 작업 전용 입력에서 모든 답을 unknown으로 만든 합성 응답을 먼저 구성하고 고정한 수학으로
채점합니다. 정답을 복사해 만점 응답을 만들지 않습니다. 의도적인 대조 응답은 사례 7개·질문 21개,
답할 수 있는 정답 14개·필수 unknown 7개입니다.

| 대조 항목          | 예상 합성 값 |
| ------------------ | ------------ |
| 답한 항목의 정확도 | 0/0, null    |
| 작업 coverage      | 0/21         |
| 필수 unknown 처리  | 7/7          |
| 잘못된 유보        | 14/14        |
| 무효 사례          | 0/7          |

이는 의도적인 합성 수학 검사이지 정적 baseline·모델 품질·독립 검토·비교 완료가 아닙니다.
인용/설명의 뒷받침·지연·제공자 사용량·반복·검토 노력·워크플로 관찰은 미측정/null로 둡니다.

`reference_inputs(root)`는 작업 전용 공개 입력을 읽습니다. `load_reference(root)`는 고정한
스냅샷 파일 세 개와 신뢰하는 직접 관리 checkout/제공한 root 양쪽의 고정 수학을 엄격히 확인하며
대상 root의 모듈을 동적으로 import하지 않습니다. 소스 바이트 검사이지 Python 메모리 증명이나
악의적인 파일시스템 sandbox가 아닙니다. `score_reference(root, responses)`는 호출자가 정규화한
응답 기록을 받아 기존 수학으로 채점합니다. 어느 API도 제공자를 호출하거나 내장 소스를 import/실행·
worker/워크플로를 실행하지 않으며 실제 프롬프트/모델/시험 정책을 제공하지 않습니다. 제품 명령/
스키마 변경·릴리스·위험 수용도 추가하지 않습니다.

## 작업 종류와 비교 입력

각 시나리오는 종류별 질문을 하나씩 포함합니다.

| 종류        | 결론을 낼 수 있는 범위                                             | 추론하면 안 되는 내용                                     |
| ----------- | ------------------------------------------------------------------ | --------------------------------------------------------- |
| 선언        | 해당 목록 질문 범위의 소스 라우트·의존성·scope 선언입니다.         | 선언만으로 런타임 실행이나 강제를 입증하지 않습니다.      |
| 정책 의도   | 시나리오에 명시적으로 제공한 공개·제한 의도입니다.                 | 애플리케이션이 그 의도를 강제한다고 결론 내리지 않습니다. |
| 런타임 보장 | Unknown: 소스 전용 사례로 일반적인 HTTP 인가를 입증할 수 없습니다. | 엔드포인트 통과·확인한 취약점·보안 보장이 아닙니다.       |

예약 사례는 공개된 assistant 작성 자료이지 비밀 자료·독립 인증 자료·모델이 보지 않았음이 입증된
holdout이 아닙니다. 해당 사례로 프롬프트를 조정하지 않습니다. 노출·사용 이력을 기록하고 개발
사례를 새로운 holdout으로 이름만 바꾸지 않습니다. 사례 7개는 소규모 기술적 비교용이지 대표성 있는
모집단이나 통계적으로 입증된 우월성의 근거가 아닙니다.
수용한 정책 값은 restricted 4개·mixed 2개·public 1개입니다. 개발용은 restricted 2개·mixed
1개·public 0개를 유지하고 예약용은 restricted 2개·mixed 1개·public 1개입니다. 예약 평가에도
Public 답이 추가됐지만 public 대조 항목 하나로 대표성 있는 범위를 확보하지는 못합니다.
여전히 작고 불균형한 정책 분류 초안입니다. 새 대조 항목은 정보용
GET 라우트 2개에 공개 의도를 명시하며 일반 의존성은 서식 처리일 뿐 인가 근거가 아닙니다.
공개 의도는 명시적으로 제공한 정책에서 읽으며 인증 의존성 부재나 `Depends` 존재에서 추론하지
않습니다. 런타임 강제를 입증하지도 않습니다. 수용한 참고 정답 값은 라우트 선언 2개·공개 의도·
unknown 런타임 보장이며 수용이 독립 검토나 런타임 보장을 뜻하지는 않습니다.

명시적 정책 질문은 의도를 읽는 대조 항목이지 접근통제 강제 여부의 검사가 아닙니다. Unknown 보장
질문 7개에는 의도적으로 런타임 근거가 없으며 일반적인 불확실성 조절 능력을 입증하지 않습니다.
대조 항목을 별도로 채점하고 합계로 AI의 이점을 주장하지 않습니다. 소스 선언의 정답은 파서와의
자기 일치가 아닙니다. Keyword-path 사례의 소스 선언은 지원 inventory가 하나만 내보내더라도
2개입니다. 불완전한 inventory는 하한일 뿐 올바른 전체 소스 개수가 아니며, 정적 baseline은 입증하지
못한 전체 개수의 답을 유보해야 합니다.

v1 참고 정답 스냅샷은 작업 문구·소스/정책 범위를 고정합니다. 아래 오프라인 응답 계약은 개발용
인터페이스이지 실제 시험 전체 동결이 아닙니다. 향후 시험 전에 응답 계약을 별도로 확인하고 실제
프롬프트·모델/설정·반복 예산을 고정합니다. 비교 모드는 다음과 같습니다.

1. 정적 전용: 결정적으로 확인한 지원 범위의 선언 사실만 답하고 정책 해석·런타임 보장은 유보합니다.
   평가자 정답을 읽어 정적 답을 만들면 안 됩니다.
2. 모델 전용: 허용한 소스·명시한 정책·질문을 제공하되 AuthZest 추출 근거는 제외합니다.
3. 근거 보조: 같은 소스·정책·질문·모델 설정에 AuthZest 추출 근거만 추가합니다. 이 추가 근거가
   의도한 입력 차이입니다.

두 AI 모드의 정확한 모델 식별자·지시·소스 범위·시험 정책을 같게 합니다. 불가피한 차이·프롬프트/
adapter/report 버전·내용 식별자·반환된 모델 ID를 기록합니다. 예상 정답·검토 자료·정답을 드러내는
메타데이터·레이블을 어느 입력에도 넣지 않습니다. 토큰 수가 같을 필요는 없으며 동일 비용을 주장하는
대신 실제 제공된 사용량을 기록합니다. 반복 수·순서는 시험 전에 정하고 실패를 보존하며 사례별 변동을
보고합니다. 기존 과거 scorer는 질문 ID `policy`를 특별 취급하므로 새 작업 종류의 scoring 구현이
아닙니다. v1 helper는 오프라인 사전 검사/채점과 합성 대조 응답만 제공하며 실제 실행기·모델 결과·
제공자 연동은 아닙니다.

## 오프라인 비교 패킷과 엄격한 응답 계약

`scripts/evaluation_response.py`는 제품 스키마를 바꾸지 않는 별도 평가 응답 스키마 `0.1`을
정의합니다. 정확히 `schema_version`, `kind`, `task_id`, `request_id`, `answers`만 포함하는 완전한
크기 제한 JSON 객체 하나를 받으며 `kind`는 `evaluation-comparison-response`입니다. 각 답 기록은
정확히 `question_id`와 `answer`만 포함하며 요청한 질문마다 하나씩 있어야 합니다. 중복 키/답·질문/
필드 누락·추가·잘못된 연결 값·비정규 값은 사례 전체를 무효로 만듭니다. 문자열을 보정하지 않습니다.
`""`는 알려진 빈 정렬 CSV 집합이고 JSON null만 unknown입니다. 원본 응답 누락은 성공한 unknown이
아닌 누락 상태로 유지합니다.

`scripts/evaluation_comparison.py`는 같은 소스·명시적 정책·질문·답 형식·공통 개발 초안 지시를
사용하는 세 모드 슬롯을 만듭니다. 근거 보조에만 기존 core `parse_source`의 메모리 내 선언 근거를
추가하며 모듈을 독립적으로 파싱하고 소스를 import·파일화·실행하지 않습니다. 근거는 항상 partial로
표시합니다. 모듈 간 router/include 맥락과 callable 의존성 그래프는 미해결이고 deferred 선언은
호출/배포를 입증하지 않으며 진단/파싱 오류도 유지합니다. 추출한 선언은 접근통제나 전체 목록의
증명이 아닙니다.

불투명 `task_id`는 작업 전용 소스/정책/질문에 연결하며 `request_id`는 모드와 payload에서 파생해
다른 요청/모드의 응답을 거부합니다. 두 AI payload는 선언 근거와 파생 request ID만 다르며 공통
초안 지시는 동결한 실제 프롬프트가 아닙니다. 잠재 제공자 payload에서 사례 이름·분할·참고 정답
manifest/후보 해시·예상 정답·이유·검토 메타데이터를 제외합니다. 평가자 계획 자체에는 사례 매핑이
있으며 **제공자 입력이 아닙니다**. 해시 연결은 신원 인증이나 비밀성 주장이 아닙니다.

저장소 루트에서 계획이나 명시적인 합성 dry run을 준비합니다.

```bash
python -m scripts.evaluation_comparison
python -m scripts.evaluation_comparison --json
python -m scripts.evaluation_comparison --dry-run
python -m scripts.evaluation_comparison --dry-run --json
python -m scripts.evaluation_comparison --dry-run --fault missing

```

모든 패킷과 mock 응답을 먼저 구성한 뒤 채점용 참고 정답을 읽습니다. Dry run의 모든 모드 슬롯은
`static-only`까지 합성 null 답을 사용하며 아래 별도로 제공하는 등록 정적 adapter를 쓰지 않습니다.
정적 baseline이나 모델 품질을 측정하지 않습니다. 각 모드는 사례 7개·질문 21개·답할 수 있는 정답
14개·필수 unknown 7개를 따로 유지합니다. Fault는 각 모드의 첫 사례에 적용합니다. 수학 경계에서
누락 응답은 `None`, 무효 응답은 `[]`로 전달하며 실패 종류·분모를 유지합니다. 무효 사례에는
unknown 점수를 주지 않으며 합성 질문 기회 63개를 AI 품질 점수로 합산하지 않습니다.
`--fault`에는 `--dry-run`이 필요합니다.

독립 검토 증명·실제 프롬프트/모델/설정/반복 동결은 후속 작업입니다. 제공자 호출이나
실제 모델 시험은 구현하지 않습니다. v1/원본 참고 정답 바이트·고정 수학·과거 기록·제품 스키마/버전·
위험 수용·릴리스는 바꾸지 않으며 #84는 체크 항목 7개 모두 미완료인 OPEN을 유지합니다.

## 등록 정적 전용 소스 관찰

별도 `scripts/evaluation_static.py` adapter는 작업 전용 digest에 연결한 명시적 선언 query registry를
사용하며 예상 정답을 저장하거나 일반 자연어 질문을 해석하지 않습니다. 미등록 작업이나 변경된
질문에는 답을 유보합니다. 기존 core 파서의 메모리 내 관찰에서 소스 HTTP decorator 선언을 세거나
literal method/path의 직접 `Security` scope를 추출합니다. AST coverage와 파서 선언 위치를 대조하며
진단·모호성·coverage 누락·모듈 간 조합 한계가 있으면 입증하지 못한 전체 값을 내지 않고 unknown으로
둡니다. 이 adapter의 정책 의도와 런타임 보장은 항상 unknown입니다.

이 매핑은 공개된 v1 작업과 정답을 이미 알 수 있는 개발 맥락에서 작성합니다. 답 생성 시 정답 파일을
읽지 않아도 독립/블라인드/미노출 holdout이 되지는 않습니다. 고정 소스 작업의 기술적 정적 관찰로
보고하며 일반 벤치마크 성능·모델 가치·독립 검토/채점 기준 완료로 해석하지 않습니다.

같은 경로를 두 app이 쓰더라도 서로 다른 소스 선언은 각각 셉니다. Deferred factory 선언은 소스
선언이지 호출/배포 증명이 아닙니다. 직접 scope query는 상속된 `Security`와 callable-provider
그래프를 제외합니다. 일반 의존성이나 scope 선언도 접근통제 강제를 입증하지 않습니다. 등록 query는
전체 Python 해석·일반 저장소 coverage·HTTP/런타임 정확성을 보장하지 않습니다.


이 선택은 고정한 직접 관리 작업 7개 범위의 결정적 소스 전용 관찰이며 모델 비교가 아닙니다. 사례

payload는 그대로이며 기본 명령은 여전히 계획만 준비합니다. `--dry-run`은 모든 모드에서 합성 null을 쓰며

반복·새 호출에 응답을 연결할 수 없습니다. 수집/실행은 미구현입니다. `answer_contract_descriptor_id`는

## 후보와 독립적인 오프라인 측정 수학

소스 checkout 전용 모듈 `scripts/evaluation_metrics.py`는 일반적인 측정 수학을 후보 읽기·평가와
분리합니다. API는 `score_cases(cases, responses)`이며 `cases`는
`CaseSpec(id, split, questions)`의 tuple, 각 `questions`는
`QuestionSpec(id, family, answer_format, expected)`의 tuple입니다. 각 예상 정답은 canonical
문자열 또는 `None`(JSON null로 표현하는 unknown)입니다. 응답은 사례 ID를 정확히 `question_id`와
`answer`만 포함하는 기록의 list에 연결하며, 사례 응답이 없으면 `None`에 연결합니다.

답 형식은 정확한 canonical 십진수·정렬된 CSV·boolean·정책 문자열을 요구합니다. 공백 제거·형변환·
정렬·정규화 등으로 답을 보정하지 않습니다. 빈 문자열은 빈 정렬 CSV 답에만 유효하며 `None`만
unknown입니다. 잘못되거나 누락·추가·중복된 답 기록은 해당 사례 전체를 무효로 만들지만 질문·사례
분모를 제거하지 않습니다. 종류별·분할별 요약은 그룹 비율을 평균하지 않고 개수를 합산한 뒤 비율을
계산합니다. 정의할 수 없는 비율은 null로 둡니다. 인용/설명의 뒷받침·지연·제공자 사용량·반복·검토
노력·워크플로 지표는 이 모듈이 측정하지 않으며 placeholder를 0이 아닌 null로 유지합니다.

이 독립 모듈에는 CLI나 파일/네트워크/제공자/소스/실행기 import가 없습니다. 제품 명령·스키마 완화·
후보 adapter·실제 비교 하니스가 아닙니다. 합성 데이터 전용 테스트는 실제 7사례·21질문 후보를
읽거나 채점·동결·승인하지 않으며 후보 데이터·연결 값·과거 평가 자료는 그대로 유지합니다.
저장소 루트에서 실행합니다.

```bash
python -m pytest tests/test_evaluation_metrics.py
```

이 명령은 합성 단위 데이터로 일반 수학만 검사합니다. 통과해도 후보 정답의 정확성이나 측정한 모델
품질 결과를 입증하지 않습니다. 별도 v1 helper가 이제 수용한 참고 정답 스냅샷을 이 수학에 연결합니다.
독립 검토 증명과 향후 실제 비교에는 이 프로토콜의 다른 경계를 그대로 적용합니다.

## 사전에 정할 측정 규칙

선언·정책 의도·런타임 보장 결과를 구분합니다. 한 모드의 한 반복에는 질문 기회 21개가 있으며
종류별 7개·개발용 9개·평가 예약용 12개입니다. 수용한 정답은 답할 수 있는 질문 14개와 unknown이
필요한 질문 7개입니다. 이 참고 정답 분모는 v1에 고정됐습니다. 이후 변경에는 새로 검토한 버전/식별자가
필요하며 분모를 알리지 않고 바꾸거나 v1 해시를 갱신하지 않습니다. 실제 시험 수나 반복 예산은 고정하지
않습니다.

| 측정               | 분자 / 분모                                                                               |
| ------------------ | ----------------------------------------------------------------------------------------- |
| 답한 항목의 정확도 | 올바른 비-unknown 답 / 모든 비-unknown 답이며, unknown이 필요한 질문에 답하면 오답입니다. |
| 작업 coverage      | 비-unknown 답 / 전체 질문 기회 21개입니다.                                                |
| 전체 대비 정답률   | 올바른 비-unknown 답 / 전체 21개이며, 답할 수 있는 항목 14개 대비 값도 별도로 보고합니다. |
| 필수 unknown 처리  | 올바른 unknown 응답 / unknown이 필요한 정답 7개입니다.                                    |
| 잘못된 유보        | 답할 수 있는 질문에 대한 unknown 응답 / 답할 수 있는 정답 14개입니다.                     |

측정 가능한 로컬 지연·제공자 사용량·반복·사람 검토 시간을 출처와 함께 기록합니다. 측정하지 않은
