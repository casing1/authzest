# 과거 평가 자료 목록

[문서 목차](../INDEX.md) · [English](../../../development/EVALUATION_INVENTORY.md) · 한국어

이 소스 checkout 개발 도구는 [#84](https://github.com/casing1/authzest/issues/84)의 준비 단계인
[#108](https://github.com/casing1/authzest/issues/108)을 위해 기존 평가 관련 자료를 추적합니다.
자료를 실행하지 않고 누락되거나 변경된 파일 바이트를 검출합니다. 새로운 벤치마크를 선택·동결하거나
정답 레이블을 승인하거나 모델을 비교하거나 #84를 완료하지 않습니다. 패키지의 `authzest` 명령이나
배포된 alpha.3 기능이 아닙니다.

## 목록 검사 실행

Python 3.12 이상으로 저장소 루트에서 실행합니다.

```bash
python scripts/check_evaluation_inventory.py
python scripts/check_evaluation_inventory.py --json
```

기본 출력은 사람이 읽기 쉬운 간결한 무결성 요약입니다. `--json`은 기계가 읽을 수 있는 결과를
출력합니다. 어느 형식도 제공자 호출, 네트워크 사용, fixture·정책 소스 import, 대상·정책 실행,
평가 수행, 파일 변경, 패치 적용, 승인 부여를 하지 않습니다.

| 종료 | 의미                                                                                 |
| ---- | ------------------------------------------------------------------------------------ |
| `0`  | manifest 스키마와 열거된 자료의 바이트 해시가 일치합니다.                            |
| `1`  | 잘못된 manifest·경로, 자료 누락, 읽기 실패, 자원 제한 또는 바이트 해시 불일치입니다. |
| `2`  | 잘못된 명령줄 사용입니다.                                                            |

종료 `0`은 벤치마크 통과, 올바른 레이블, 검토 완료, 실행 허가 또는 보안 보장이 아닙니다.
검사기는 manifest의 선언이 파일을 정확히 설명하는지 입증하지 않습니다.

## 과거 자료 그룹 구분

[manifest](../../../../tests/fixtures/evaluation_inventory.json)는 저장소 상대 자료 경로,
원본 파일 바이트의 SHA-256 해시와 선언된 과거 맥락을 기록합니다. 각 그룹은 목적과 검토 이력이
다르므로 하나의 벤치마크 분모로 합산하지 않습니다.

| 과거 자료 그룹      | 선언된 맥락                                                                                                                                                   | 새로운 #84 평가에서의 한계                                                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| #33 선언·mock 자료  | 소스 사례 6개, 질문 10개이며 개발 사례 3개와 과거에 선언된 held-out 사례 3개입니다. assistant 작성 레이블에는 승인된 정책 기준과 코드로 대조한 값이 있습니다. | 독립적인 벤치마크 검토를 받은 자료가 아닙니다. 기존 분할과 corpus 식별자를 보존하며, 과거 held-out 이름만으로 비공개이거나 새롭게 독립적인 holdout임을 입증하지 않습니다. |
| 소유 정책 개발 사례 | assistant가 작성한 예상 레이블 28개이며 정책 기준은 승인됐지만 개별 레이블 검토는 대기 중입니다.                                                              | 개발 회귀 사례이지 승인된 벤치마크 레이블이 아닙니다.                                                                                                                     |
| #77 소유 사례 검토  | 원래 제안 기록과 별도 유지관리자 검토에 모델 작성 사례 10개가 있습니다. 개별 레이블은 기록된 채팅 결정으로 승인됐으며 검토자 기록은 인증된 것이 아닙니다.     | 작성 주체와 원래 pending·draft 기록을 보존합니다. 이후의 개별 검토는 다른 레이블이나 새 독립 벤치마크에 대한 포괄 승인이 아닙니다.                                        |
| #80 정책 관찰       | 별도 recipe 버전으로 동일한 검토 사례 10개를 관찰한 과거 기록 2개입니다.                                                                                      | 고유 사례 20개나 새로운 실행, 현재 코드의 입증이 아닙니다. 과거의 1회 실행 승인은 소진됐습니다.                                                                           |
| 검토된 합성 수정 쌍 | assistant 작성 합성 개발 레이블 8개에 개별 검토 기록이 있으며, 소스 모듈에 수정 쌍과 검토 맥락이 포함됩니다.                                                  | 실행 관찰을 추가하지 않습니다. 레이블·소스 검토는 실행·패치 적용·새 벤치마크 사용 승인이 아닙니다.                                                                        |

모든 그룹은 새로운 #84 평가에서 참조 전용이며 후보 선택은 `not-selected`, 독립 벤치마크 검토는
`not-established`입니다. 이 새 평가 상태는 과거 레이블 승인을 철회하거나 #33의 기존 과거 분할을
바꾸지 않습니다. 소스 맥락 파일은 해석을 돕는 자료이지 추가 사례나 독립적으로 검토된 레이블이 아닙니다.

기존 canonical corpus·사례·검토·소스·계획 식별자는 변경하지 않습니다. 파일 전체 바이트의 SHA-256
해시는 canonical JSON 객체나 여러 파일로 구성된 corpus의 digest와 다른 식별자입니다. 서로 대체하지
마세요. 기존 의미·출처 회귀 테스트가 과거 연결 관계를 별도로 확인하며, 이 목록 검사기는 스키마·경로·바이트만
검증합니다.

## 검증과 한계

검사기는 엄격한 manifest 스키마를 사용하며 안전하지 않은 저장소 상대 경로, 심볼릭 링크, 일반 파일이
아닌 자료, 누락 파일, SHA-256 해시 불일치를 거부합니다. 읽기 상한은 manifest 256 KiB, 자료별
4 MiB, 전체 자료 파일 64개입니다. 소스를 import하거나 실행하지 않고 데이터로 읽습니다.

저장소는 `.gitattributes`로 목록에 포함된 텍스트 경로의 checkout 줄바꿈을 LF로 고정합니다.
검사기는 줄바꿈을 정규화하지 않으므로 해당 바이트를 CRLF로 바꾸면 여전히 변경으로 보고합니다.

해시 일치는 진위 인증이 아닙니다. manifest와 자료를 함께 바꾸면 둘을 일치시킬 수 있습니다.
manifest의 개수·작성 주체·검토 설명·선택 상태와 그 밖의 과거 설명은 선언이며 기계가 입증한 사실이
아닙니다. 검사기는 독립 검토, 레이블 정확성, 동의, 현재 구현 동작, 모델 품질 또는 보안을 입증하지
못합니다. 적대적인 동시 파일 변경을 격리하는 sandbox가 아니므로 신뢰하는 도구와 안정된 checkout에서
사용합니다.

자료를 의도적으로 바꿀 때에는 출처와 관련 의미 검증 테스트를 검토한 뒤 목록 해시를 갱신합니다.
변경 검출을 없애기 위해 기계적으로 해시를 새로 만들지 마세요. 과거 기록과 승인을 보존하며 새로운 관찰이나
검토를 뜻하는 자료는 별도로 기록합니다. 같은 범위의 PR에서 목록 검사와 관련 테스트를 다시 실행합니다.

## #84에 남은 작업

독립적인 개별 정답 레이블 검토, 유지할 작업 선택, 새로운 holdout, 비교 가능한 입력·분모, 판단 유보
처리와 향후 세 모드 평가는 [모델 전략](MODEL_STRATEGY.md)을 따릅니다. 해당 평가셋의 선택·동결에는
별도로 기록한 결정이 필요합니다. 이 목록은 성능 측정이나 모델 품질 결론을 제공하지 않습니다.
실제 모델 호출, 소스 공유, 정책 실행 또는 패치 적용에는 여전히 각각 범위가 정해진 결정이 필요하며,
목록 검사는 이전 승인을 소진하거나 갱신하지 않습니다.
