## 이번 릴리스에서 할 수 있는 일

- **외부 단일 파일 수정(`repo-fix`).** 다른 폴더의 독립 FastAPI 파일 하나, 직접 쓴 정책, 직접 검토한 GET
  사례 4–8개를 지정합니다. 공유할 요청을 승인하면 Codex가 HTTP PoC 요청과 한 파일 수정안을 씁니다.
  AuthZest는 정확한 수정 전·후 소스를 격리된 A/B 컨테이너에서 실행하고 각 응답을 검토한 답과 비교합니다.
  수정 전에 결함이 재현되고 수정 후 모든 사례가 일치할 때만 원본에 쓰기를 제안합니다. 원본 쓰기는 별도
  승인이 필요하고 백업을 남기며 `repo-restore`는 이후 편집이 없을 때 이를 되돌립니다. 효과마다 한 번만
  쓰는 코드를 따로 묻습니다.
- **저장 결과 보기.** `--json`으로 전체 결과를 저장해 로컬 대시보드에서 엽니다. 기록한 소스로 diff를 다시
  만들고 PoC, 수정 전·후 사례별 결과, 원본 쓰기와 복구 상태를 보여 줍니다. 모순되거나 변조된 기록은
  거절합니다.
- **오프라인 FastAPI 목록.** 검사 대상 코드를 import하거나 실행하지 않고 app/router 등록, prefix, 의존성
  선언을 찾아 읽기 쉬운 CLI나 JSON으로 보여 줍니다.
- **관리 중인 owner-read 예제.** 동봉한 보관 노트 시나리오의 Codex 방어 테스트·수정 흐름은 CLI와 선택형 GUI
  작업 공간에서 계속 사용할 수 있습니다.

## 확인한 동작

2026-11-25 macOS arm64에서 실제 Codex 모델(`gpt-5.6-sol`)과 Docker Desktop 29.9.3으로 동봉 시연
(`examples/external_notes_app`)을 끝까지 실행했습니다. 새 가상환경에 설치한 wheel로도 한 번 더 실행했습니다.

- 모델 PoC는 지정 회귀(소유자가 아닌 사용자가 다른 사람의 노트를 읽는 경우)와 같았습니다.
- 수정 전에는 검토한 사례 5/5가 기대한 답과 일치해 결함을 재현했고 수정 후에도 5/5가 일치했습니다.
  모든 컨테이너를 삭제했습니다.
- 백업과 함께 원본에 썼습니다. 이후 사용자 편집이 있는 동안 `repo-restore`는 복구를 거절했고 편집을
  되돌린 뒤에는 원본을 복구했습니다.
- 저장 결과는 대시보드에서 재구성한 diff와 함께 열렸습니다.

일치는 검토한 사례 5개에만 해당하며 앱 전체를 보증하지 않습니다. 승인과 쓰기 사이에 생긴 편집의 거절은
회귀 테스트로만 확인했습니다.

## 설치 경로 고르기

| 경로                                                 | 지원 용도                                                                                                                         |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 소스 checkout 또는 이를 빌드한 wheel(Python 3.12)    | macOS arm64와 Docker Desktop에서 `repo-fix` / `repo-restore`를 포함한 모든 CLI 명령. A/B runtime은 checkout에서 한 번 준비합니다. |
| UI 추가 구성과 프런트엔드 빌드를 갖춘 편집 가능 소스 | 로컬 대시보드: 정적 목록, 저장 결과 보기, owner-read GUI 작업 공간                                                                |
| 태그별 Linux x64, macOS arm64, Windows x64 실행 파일 | 정적 검사와 오프라인 미리보기. `repo-fix`와 활성 수정 흐름은 실행 파일로 묶인 환경에서 거절합니다.                                |

외부 수정에는 ChatGPT 계정으로 로그인한 Codex CLI `0.153.0`(다른 버전은 거절)과 그 계정에 표시되는 모델 ID도
필요합니다. 정적 목록과
저장 결과 보기는 로그인이 필요 없습니다. 실행 파일은 서명·공증하지 않았고 PyPI·npm 발행은 이번 범위가
아닙니다.

## 한계

- module 수준 app이 있는 평면 `.py` 앱 파일 하나(≤16 KiB), 정책 파일(≤8 KiB), 메모리 데이터, GET 라우트만
  지원합니다. 패키지, 고정 이미지 밖의 프로젝트 의존성, 데이터베이스, 다른 HTTP 메서드, 실제 로그인 시스템은
  지원하지 않습니다. 사용자 식별은 합성 테스트 헤더입니다.
- 사례 파일에 기대하는 답을 적습니다. 사용자가 직접 쓰고 검토하며 모델이나 컨테이너로 보내지 않습니다.
  결과의 신뢰도는 그 사례에 달려 있습니다.
- 소스 선언은 실제 인가 동작의 증거가 아닙니다. 알 수 없음·실패·거절·미실행 결과도 그대로 보여 주며,
  사례 일치가 앱 전체의 보안을 증명하지 않습니다.
- 결정은 300초 뒤 만료되고 한 번만 쓸 수 있습니다. 쓰기를 되돌릴 필요가 없을 때까지 복구 기록을 보관하세요.
- 개발용 포맷 도구는 [#89](https://github.com/casing1/authzest/issues/89)와
  [#171](https://github.com/casing1/authzest/issues/171)에서 후보별 경고를 유지합니다.
- 의존성과 함께 배포되는 runtime 구성 요소는 각자의 라이선스를 따릅니다.
  [참고 자료·서드파티 소프트웨어](../reference/THIRD_PARTY.md)를 보세요.
