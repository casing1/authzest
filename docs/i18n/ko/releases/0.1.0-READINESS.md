## 현재 도구 경고

프런트엔드 lock과 포맷터 guard·설정 바이트는 검토한 사전검증 소스와 같습니다. 독립 picomatch는
4.0.7이며 Prettier 3.10.1에도 별도 2.3.2가 내장되어 있습니다. GitHub는
[권고를 철회](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)했지만
[CVE 원본](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/112xxx/CVE-2026-112366.json)은
PUBLISHED 상태입니다. 원본 간 불일치와 확인한 수정판이 없는 상태는
[#171](https://github.com/casing1/authzest/issues/171)에서 추적합니다.
[#89](https://github.com/casing1/authzest/issues/89)의 명시된 brace-expansion 수정 3개는 유지됩니다.

제안하는 처리는 후보별 경고와 개발 도구 가용성 노출의 계속된 추적입니다. 변경된 checkout,
직접 Prettier·편집기·API 실행 또는 guard 가정 밖의 동시 파일 변경으로 신뢰하지 않는 설정·패턴을
처리하면 작업이 지연될 수 있습니다. 검토한 checkout과
[guard 포맷 명령](../development/FORMATTING.md)을 사용하세요. 선택한 native 목록에는 별도
matcher·formatter 항목이나 프런트엔드 node_modules가 없지만, 모든 바이너리 바이트의 부재를
증명하거나 잔여 위험을 수용하는 관찰은 아닙니다.

## 수용 결정 기록 후

1. 제품 범위·근거 기준·도구 결정을 #198/#150/#171에 정확한 최종 SHA와 연결해 기록합니다.
2. 검토한 head가 바뀌지 않았는지, 필수 CI·리뷰와 릴리스 메타데이터를 확인합니다.
   발행 권한이 있을 때만 현재 main 커밋에 일치하는 v0.1.0 태그를 만듭니다.
3. guard가 있는 릴리스 파이프라인으로 검증·빌드·새 다운로드 검사를 수행합니다. native preview와
   달리 기존 고정 소유 fixture 런타임 검사(POSIX fixture 실행·Windows 명시 미지원)를 수행합니다.
   태그 실행은 모든 필수 작업 통과 후에만 자동 공개 발행합니다.
4. 공개 실행 파일·체크섬을 모두 내려받아 해당 태그 실행 산출물과 대조하고 실제 발행 기록을
   남깁니다. 실패·건너뛴 조건은 그대로 실패·미완료로 남깁니다.

이 순서는 새 제품 모델·생성 guest 실행, 비공개 원본 로그 공개나 임의 저장소 패치를 뜻하지 않습니다.
새 활성 시연에는 별도 명시 범위가 필요합니다.
