## 현재 개발 도구 경고

단독 picomatch는 4.0.7이고 Prettier 3.10.1에는 별도 2.3.2 사본도 들어 있습니다. GitHub는
[권고를 철회](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)했지만
[CVE 기록](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/112xxx/CVE-2026-112366.json)은
게시 상태입니다. [#89](https://github.com/casing1/authzest/issues/89)에서 추적하는 brace-expansion 수정 세 건은
그대로 들어 있습니다. 노출 범위는 개발·CI 가용성입니다. 바뀐 checkout을 통한 신뢰할 수 없는 설정·패턴이나
Prettier·편집기 직접 호출은 포맷 작업을 멈추게 할 수 있습니다. 검토한 checkout과
[보호된 포맷 명령](../development/FORMATTING.md)을 사용하세요.

## 릴리스 단계

1. 근거·개발 도구·발행 결정을 최종 SHA와 함께 #150, #89, #171에 기록합니다.
2. main의 릴리스 커밋 하나에서 두 언어의 `[0.1.0]` 변경 기록 날짜를 발행일로 바꿉니다. 그 커밋의 필수 CI를
   확인한 뒤 같은 커밋에 `v0.1.0`을 만듭니다.
3. 보호된 릴리스 파이프라인이 검증·빌드·새 다운로드 확인을 하게 둡니다. 고정 소유 fixture runtime 검사를
   실행하며 필수 job이 모두 통과한 뒤에만 발행합니다.
4. 공개 실행 파일과 체크섬을 모두 내려받아 태그 실행의 산출물과 비교하고 태그에서 소스 ZIP을 만든 뒤
   발행 기록을 #150에 남깁니다.

이 단계에는 모델 호출, 컨테이너 실행, 원본 쓰기가 포함되지 않습니다.
