# AuthZest

AuthZest — устанавливаемый проект с открытым исходным кодом и основным интерфейсом CLI для анализа контроля
доступа в приложениях FastAPI по их исходному коду. Сейчас ядро на Python собирает маршруты, не импортируя
и не выполняя целевое приложение. Оценка авторизации и необязательная помощь ИИ относятся к следующим
этапам разработки.

Панель React — необязательный локальный интерфейс. Для использования AuthZest не нужно публиковать веб-сайт.

> [!IMPORTANT]
> Опубликованная [предварительная версия v0.1.0-alpha.1](https://github.com/casing1/authzest/releases/tag/v0.1.0-alpha.1)
> — первый запускаемый каркас проекта. Описанные ниже распознавание владельцев маршрутов, объединение
> префиксов и связывание маршрутизаторов между файлами реализованы в `main`, но **ещё не выпущены** в этих
> исполняемых файлах. Пакет из исходников также пока показывает `0.1.0a1`; используйте коммит рабочей копии
> и [историю изменений](../../CHANGELOG.md), чтобы отличить его от опубликованной версии. Ни один из вариантов
> пока не является полноценным сканером уязвимостей.

## Что поддерживает текущий исходный код

- Распознавание статически созданных объектов `FastAPI` и `APIRouter`, включая поддерживаемые псевдонимы import.
- Поиск HTTP-маршрутов со строковыми литералами и объединение поддерживаемых префиксов маршрутизатора и регистрации.
- Связывание локальных абсолютных и относительных import с сохранением исходного файла и номера строки.
- Текстовые отчёты и JSON через команду `scan`.
- Необязательные локальные API и панель, диагностика и сборка отдельных исполняемых файлов.

Поддерживаются декораторы `get`, `post`, `put`, `patch`, `delete`, `options` и `head`.
Область статического анализа ограничена: динамические и неразрешённые объявления пропускаются. Пустой отчёт
не доказывает отсутствие endpoint или безопасность контроля доступа. См. [границы парсера](../PARSER_SCOPE.md).
Сбор зависимостей, классификация аутентификации и авторизации и выявление уязвимостей пока не реализованы.

`scan` выполняет локальный статический анализ с отключённым адаптером Codex. Команда не вызывает Codex
и не требует API key или входа в ChatGPT. Отдельная команда `doctor` может вызывать установленный Codex CLI,
как описано ниже.

## Установка CLI из исходников

Сначала установите Python 3.12 или новее и [pipx](https://pipx.pypa.io/latest/how-to/install-pipx.html);
базовая версия для разработки — Python 3.12. Эти команды
устанавливают текущий код репозитория в изолированное окружение pipx, а не пакет из PyPI:

```bash
git clone https://github.com/casing1/authzest.git
cd authzest
pipx install --python 3.12 .

authzest --help
authzest scan /path/to/fastapi-project
authzest scan /path/to/fastapi-project --json
```

Замените `/path/to/fastapi-project` на каталог своего проекта. Если команда не найдена в PATH, выполните
`pipx ensurepath` и откройте новый терминал. CLI, установленный через pipx, не требует активации venv проекта.
Примеры выбирают Python 3.12. Для другого поддерживаемого интерпретатора замените `3.12` после `--python`
на его версию или путь к исполняемому файлу.

Для обновления этой установки выполните команды в рабочей копии `authzest` на `main` без незакоммиченных изменений:

```bash
git pull --ff-only
pipx install --force .
```

Готовые файлы описаны в разделе [отдельные исполняемые файлы](#отдельные-исполняемые-файлы). Extra `ui`
устанавливает Python-зависимости backend, но обычная установка wheel/pipx не включает собранные ресурсы
панели. Для необязательной панели используйте editable-установку из исходников, описанную ниже.

## Диагностика CLI

```bash
authzest --version
authzest doctor
authzest doctor --json
```

`doctor` проверяет среду Python. Если в PATH найден `codex`, команда также запускает `codex --version` и
`codex login status` как дочерние процессы. Она не запускает ИИ-сканирование и сама не читает файлы учётных
данных. Отсутствие Codex или входа вызывает предупреждение, но не препятствует статическому сканированию.

## Среда разработки

Выполняйте команды из корня клонированного репозитория. Примеры shell рассчитаны на macOS/Linux. В Windows
PowerShell создайте venv командой `py -3.12 -m venv .venv` и активируйте через `.venv\Scripts\Activate.ps1`.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

Editable-установка использует эту рабочую копию, а extra `dev` включает необязательные зависимости backend.
Node.js/npm нужны только для работы над frontend или сборок с панелью. В CI используется Node.js 22.

## Необязательная локальная панель

После подготовки editable-среды разработки соберите и запустите панель из корня репозитория:

```bash
npm --prefix frontend ci
npm --prefix frontend run build
authzest ui --workspace /path/to/fastapi-project --host 127.0.0.1 --port 8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Backend в editable-установке находит `frontend/dist`
в рабочей копии. Без сборки `/` показывает сообщение API вместо панели.

Для разработки frontend в одном терминале с активным venv запустите
`authzest ui --workspace /path/to/fastapi-project --reload`, а в другом терминале из корня репозитория —
`npm --prefix frontend run dev`. Откройте [http://localhost:5173](http://localhost:5173); Vite перенаправляет
`/api` и `/health` на порт 8000.

Локальный сервер предоставляет `GET /health`, `GET /api/health`, `POST /api/scans` и документацию API в `/docs`.
Endpoint сканирования всегда использует рабочий каталог, выбранный при запуске сервера; тело запроса не
позволяет выбрать другой путь. Прямое сканирование через CLI использует путь, указанный локальным пользователем.
Запускайте необязательный сервер на loopback-адресе.

## Проверка

С активным venv разработки выполните:

```bash
python -m pytest
ruff check .
ruff format --check .
```

При изменении frontend также выполните:

```bash
npm --prefix frontend ci
npm --prefix frontend run lint
npm --prefix frontend run format:check
npm --prefix frontend run build
```

## Отдельные исполняемые файлы

[Опубликованная предварительная версия](https://github.com/casing1/authzest/releases/tag/v0.1.0-alpha.1)
содержит файлы для Linux x64, macOS arm64 и Windows x64, а также манифесты SHA-256. Это программы CLI,
а не графические установщики; они не включают ещё не выпущенные изменения парсера из `main`. Файлы пока
не подписаны и не нотарифицированы, поэтому ОС может предупредить о непроверенном издателе.

Для локальной сборки текущего кода активируйте venv разработки и выполните из корня репозитория:

```bash
python -m pip install -e '.[build]'
npm --prefix frontend ci
npm --prefix frontend run build
python -m PyInstaller --clean --noconfirm authzest.spec
./dist/authzest --help
```

В Windows результат находится в `dist\authzest.exe`. PyInstaller включает `frontend/dist`, если каталог
существует. Проверка тегов, контрольные суммы и публикация описаны в [руководстве по релизу](../RELEASING.md).

## Структура проекта

```text
src/authzest/
├── analyzer/   # Анализ и агрегация репозитория
├── parser/     # Разрешение маршрутов и import по AST
├── runner/     # Общий процесс сканирования
├── codex/      # Необязательный интерфейс провайдера; адаптер scan отключён
├── cli.py      # Командный интерфейс Typer
├── api/        # Необязательный транспорт FastAPI
└── models.py   # Данные отчётов ядра
tests/          # Регрессионные тесты
frontend/       # Необязательная панель React/Vite/TypeScript
docs/           # Руководства, переводы и ресурсы
scripts/        # Инструменты релиза
.github/        # Workflow CI/релиза и шаблоны для участников
```

CLI и необязательные API/UI используют одно ядро. Анализ ядра не должен зависеть от веб-сервера, React
или конкретного провайдера ИИ.
