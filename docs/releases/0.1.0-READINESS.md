## Current tooling warning

Standalone picomatch is 4.0.7; Prettier 3.10.1 also bundles a separate 2.3.2 copy. GitHub
[withdrew its advisory](https://github.com/advisories/GHSA-fc5q-39xc-vjpf), while the
[CVE record](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/112xxx/CVE-2026-112366.json)
remains published. The three brace-expansion fixes tracked in
[#89](https://github.com/casing1/authzest/issues/89) remain present. The exposure is development and
CI availability: untrusted configuration or patterns through a changed checkout, or a direct
Prettier/editor invocation, can stall formatting. Use reviewed checkouts and the
[guarded formatting commands](../development/FORMATTING.md).

## Release steps

1. Record the evidence, tooling and publication decisions with the final SHA in #150, #89 and #171.
2. In one release commit on main, replace the `[0.1.0]` changelog date in both languages with the
   publication date. Confirm required CI on that commit, then create `v0.1.0` at it.
3. Let the guarded release pipeline validate, build and verify fresh downloads. It runs the fixed
   owned-fixture runtime checks and publishes only after all required jobs pass.
4. Download every public executable and checksum, compare them with the tag run's artifacts, build
   the source ZIP from the tag, and record the publication receipt in #150.

No model call, container run or original write is implied by these steps.
