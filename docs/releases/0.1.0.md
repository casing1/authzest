Release notes prepared on **2026-11-23 KST**. These notes describe the intended course release;
their presence does not establish publication. Check [GitHub Releases](https://github.com/casing1/authzest/releases)
for available tags, files and checksums. [Candidate decisions](0.1.0-READINESS.md) remain separate.

## What this release delivers

- **Offline FastAPI inventory.** Find supported application/router registrations, prefixes and
  dependency declarations without importing or running the scanned repository. Reports include
  source locations, diagnostics and partial-analysis status in readable CLI or JSON output.
- **Codex-assisted defensive test and repair.** For the maintained synthetic archived-note case,
  preview the exact source/policy request and ask the replaceable Codex adapter to author a
  regression test and one-file availability-rule repair. No-change and unknown remain valid outcomes.
- **Reviewed private-copy workflow.** Review runtime, sharing, copy, before, exact diff, application,
  after and restoration separately. Check the generated regression and seven maintained controls
  in reviewed network-disabled Linux guests. Application changes only a new private copy.
- **Local English/Korean GUI.** Browse static routes and saved JSON, or explicitly enable the same
  owner-read engine with current typed decisions. Inspect code, differences, observations and recovery;
  download the full result. Terminal runs stop repeated session reads. No website deployment is required.

The fixture's intended comparison is **before 6/7 policy matches → after 7/7**, including the owner
reading an archived note (HTTP 403 → 200). Inspect generated-test results, independent controls,
cleanup and restoration as well. These expected values are not a guarantee for a new model response.

## Choose an installation route

| Route                                                           | Supported use                                                                                                |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Editable source, UI extra and locked frontend build             | Current local dashboard; active owner-read GUI/CLI on POSIX non-frozen installations with a reviewed runtime |
| Regular Python wheel or source-installed pipx CLI               | CLI commands; dashboard assets are not bundled in the wheel                                                  |
| Tag-specific Linux x64, macOS arm64 and Windows x64 executables | Static scan and offline previews; active owner-read repair is unsupported in frozen binaries                 |

Start with the [README](../../README.md) and [course walkthrough](../guides/COURSE_DEMO.md).
The active workflow requires Python 3.12, a trusted Codex CLI **0.153.0**, an existing
ChatGPT login and the [reviewed private runtime configuration/image](../development/GENERATED_REPAIR_CONTRACT.md#running-the-approved-copy-workflow).
The GUI additionally requires an editable source installation with the UI extra and built frontend assets.
Static inventory and saved-result viewing need no model login. The executable files are unsigned
and not notarized; PyPI/npm publication is outside this release process.

## Limits to retain in demonstrations

- AI repair supports **one maintained synthetic scenario**. Selecting a static workspace does not
  send or repair that repository. General FastAPI repair, arbitrary target execution and an
  independent model-comparison benchmark are not delivered by this release.
- A source declaration is not proof of runtime authorization. Partial analysis, unknown and
  not-run results remain visible; successful controls do not prove general application security.
- GUI activity reports host workflow stages, not a live Codex token stream. Saved JSON is imported
  as unverified data and does not grant execution authority or resume a prior run.
- Decisions expire and are single-use. Cancellation after application can leave recovery work;
  check the actual restoration/cleanup state and retain required private recovery files.
- The reviewed guest controls have documented isolation and availability limits. See the
  [workflow contract](../development/GENERATED_REPAIR_CONTRACT.md) and [security policy](../../SECURITY.md).
- Development formatting retains a candidate-specific warning and tracking under
  [#89](https://github.com/casing1/authzest/issues/89) and [#171](https://github.com/casing1/authzest/issues/171).
  See [formatter evidence](../development/FORMATTING.md); these notes do not accept that risk.
