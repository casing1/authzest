## What this release delivers

- **External single-file repair (`repo-fix`).** Point AuthZest at one self-contained FastAPI file in
  another folder, a policy you wrote and 4–8 GET cases you reviewed. After you approve the exact
  request, Codex writes an HTTP PoC request and a one-file repair. AuthZest runs the exact before
  and after source in isolated A/B containers and compares each response with your reviewed
  answers. Only when the defect reproduces before and every case matches after does it offer to
  write the original. That write needs its own approval and keeps a backup; `repo-restore` undoes it
  unless the file was edited since. Every effect asks for its own single-use code.
- **Saved-result viewing.** Save the complete result with `--json` and open it in the local
  dashboard. The viewer rebuilds the diff from the recorded source and shows the PoC, each case
  outcome before and after, and the original write and recovery state. It refuses contradictory
  or tampered records.
- **Offline FastAPI inventory.** Find application/router registrations, prefixes and dependency
  declarations without importing or running the scanned code, in readable CLI or JSON output.
- **Maintained owner-read example.** The earlier Codex-assisted defensive test and repair for the
  bundled archived-note scenario remains available in the CLI and the opt-in GUI workspace.

## Verified behaviour

On 2026-11-25 the bundled demo (`examples/external_notes_app`) ran end to end with a real Codex
model (`gpt-5.6-sol`) and Docker Desktop 29.9.3 on macOS arm64. The run was repeated from a wheel
installed into a fresh virtual environment:

- The model's PoC matched the designated regression: a non-owner reading another user's note.
- Before the repair 5/5 reviewed cases matched the expected answers, reproducing the defect. After
  the repair 5/5 matched. Every container was removed.
- The original was written with a backup. `repo-restore` refused while a later user edit was
  present and restored the original once that edit was removed.
- The saved result opened in the dashboard with the rebuilt diff.

Matching covers those five reviewed cases, not the whole application. Refusal of an edit made
between approval and the write is covered by regression tests only.

## Choose an installation route

| Route                                                           | Supported use                                                                                                                               |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Source checkout or a wheel built from it (Python 3.12)          | All CLI commands, including `repo-fix` / `repo-restore` on macOS arm64 with Docker Desktop. Prepare the A/B runtime once from the checkout. |
| Editable source with the UI extra and frontend build            | Local dashboard: static inventory, saved-result viewing and the owner-read GUI workspace                                                    |
| Tag-specific Linux x64, macOS arm64 and Windows x64 executables | Static scan and offline previews. `repo-fix` and the active repair workflows refuse to run in these frozen binaries.                        |

External repair also needs Codex CLI `0.153.0` (other versions are refused) signed in with your
ChatGPT account, and a model ID that the account lists. Static inventory and saved-result viewing need no login. The executables are
unsigned and not notarized; PyPI and npm publication are outside this release.

and the [course walkthrough](../guides/COURSE_DEMO.md).

## Limits

- One flat `.py` application file (≤16 KiB) with a module-level app, a policy file (≤8 KiB), in-memory
  data and GET routes. No packages, project dependencies beyond the pinned image, databases, other
  HTTP methods or real login systems. Identities are synthetic test headers.
- The case file holds the expected answers. It is written and reviewed by you, never sent to the
  model or a container, and the result is only as good as those cases.
- A source declaration is not proof of runtime authorization. Unknown, failed, declined and not-run
  results stay visible; matching cases do not prove general application security.
- Decisions expire after 300 seconds and are single-use. Keep recovery records until you no longer
  need to undo a write.
- Development formatting keeps a candidate-specific warning under
  [#89](https://github.com/casing1/authzest/issues/89) and [#171](https://github.com/casing1/authzest/issues/171).
- Dependencies and bundled runtime components keep their own licenses; see
  [references and third-party software](../reference/THIRD_PARTY.md).

## Roadmap

The original goal is general FastAPI authorization analysis with automatic patching. After 0.1.0:
call-graph analysis across files, multi-file proposals, automatic runtime setup for project
dependencies, and adapters for real authentication schemes.
